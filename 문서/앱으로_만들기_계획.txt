        앱으로 만들기 — 지금 구조와 앞으로 할 일
                                          2026-09-17

0. 결론 먼저
────────────────────────────────────────────────────────────────

  · 원하시는 구조("웬만한 건 폰 안에서")는 이미 거의 되어 있습니다.
    AI 판별 · 글자 인식 · 사진 매칭 · 3D 건물 · 길찾기 —
    전부 폰 안에서 돌아갑니다. 서버로 나가는 건 제보 전송과
    관리자 화면뿐입니다. 이게 정확히 원하시던 모양입니다.

  · 지금 딱 하나 빠진 게 있습니다.
    AI 모델 파일과 글자인식 파일을 매번 인터넷에서 받아옵니다.
    건물 안에서 신호가 약하면 느리거나 아예 안 됩니다.

  · Capacitor 로 감싸면 아이폰·안드로이드 둘 다 하나로 해결되고,
    위 문제도 같이 사라집니다. 코드를 새로 짜지 않습니다.


1. 지금 어디서 무엇이 도는가
────────────────────────────────────────────────────────────────

  [폰 안에서 도는 것 — 인터넷 필요 없음]
     · 사진으로 위치 판별 (MobileNet, 기준벡터 2,705개 내장)
     · 호실 번호판 글자 읽기 (Tesseract)
     · 3D 건물 보기 · 길찾기
     · QR 읽기
     · 인터넷이 끊기면 제보를 폰에 저장해 뒀다가 나중에 보내기

  [인터넷이 필요한 것]
     · 처음 페이지 열 때 index.html 받기   압축 전송 약 14.9 MB
     · AI 모델 파일                             7.6 MB   ← CDN 에서
     · 글자인식 파일                           12.0 MB   ← CDN 에서
     · 제보 보내기 / 관리자 로그인·승인 (Firebase)

  앞의 셋은 앱으로 감싸면 전부 사라집니다.
  마지막 하나만 남고, 그건 관리자용이니 그대로 두면 됩니다.

  ※ 참고 : 로컬 파일을 먼저 찾고 없으면 CDN 으로 가는 코드는
    이미 들어 있습니다. 그런데 깃허브 저장소에는 index.html
    하나만 올려 두어서, 지금은 항상 CDN 으로 갑니다.


2. 세 가지 방법 — 무엇을 고를까
────────────────────────────────────────────────────────────────

                        ① 지금 웹     ② PWA        ③ 앱(Capacitor)
  홈 화면 아이콘          X            O            O
  오프라인 동작           X            O            O
  처음 받는 양          약 30MB      약 30MB      설치 때 한 번
  두 번째부터           캐시로 빠름   캐시로 빠름   받지 않음
  기압계(층 감지)         X            X            O
  카메라                 웹으로 됨     웹으로 됨     더 안정적
  앱스토어 등록           불필요        불필요        아이폰은 필요
  맥(Mac) 필요            X            X            O (아이폰만)
  Node/npm 필요           X            거의 X        O
  만드는 데 걸리는 시간    (이미 됨)     1~2일        1~2주

  → 최종 목표는 ③ 입니다.
    다만 ② 를 먼저 해두면 맥 없이도 "앱처럼" 쓸 수 있어서,
    조원들·교수님께 보여주기에도 좋고 ③ 으로 갈 때 헛수고가
    되지 않습니다. (② 에서 만든 것이 ③ 에 그대로 들어갑니다)


3. ② PWA 로 먼저 가는 법 (맥·Node 없이)
────────────────────────────────────────────────────────────────

  PWA 는 "홈 화면에 설치되고 오프라인으로 도는 웹페이지" 입니다.
  깃허브 페이지에 파일 두 개만 더 올리면 됩니다.

     manifest.json      앱 이름 · 아이콘 · 시작 주소
     sw.js              오프라인 저장 담당 (service worker)

  그리고 지금 CDN 으로 가는 파일들을 저장소에 같이 올립니다.
     lib/      12.0 MB   (tf.min.js, mobilenet, tesseract)
     model/     7.6 MB   (MobileNet 가중치)

  ※ 깃허브 웹으로 끌어다 올리는 건 파일 하나당 25MB 까지라
    이 파일들은 다 들어갑니다. 다만 개수가 9개라 폴더째 올려야
    하고, 웹 화면에서는 폴더 업로드가 조금 번거롭습니다.
    한 번만 하면 끝나니 같이 해드리겠습니다.

  되는 것 : 홈 화면 설치, 두 번째부터 오프라인, 로딩 빨라짐
  안 되는 것 : 기압계


4. ③ 앱으로 감싸는 법
────────────────────────────────────────────────────────────────

  Capacitor 는 지금 index.html 을 그대로 넣어 앱으로 만듭니다.
  화면을 새로 짜지 않습니다. 껍데기만 씌웁니다.

  [준비물]
     Node (npm)              — 이 PC 에 깔아야 합니다
     Android Studio          — 윈도우에서 됩니다
     Xcode + 맥              — 아이폰용. 윈도우에서는 불가능합니다
     애플 개발자 등록 $99/년  — 앱스토어에 올릴 때만. 시연만 하면 불필요

  [맥이 없을 때]
     · 학교 실습실 맥 / 조원 중 맥 쓰는 사람에게 한 번만 빌리기
     · GitHub Actions 의 macOS 서버에서 빌드 (공개 저장소면 무료분 있음)
     · Codemagic 같은 클라우드 빌드 (오픈소스 무료 등급)
     → 어느 쪽이든 "한 번 만들어 두면" 그 뒤로는 자주 필요 없습니다

  [넣게 될 것]
     www/index.html      24.2 MB
     www/lib/            12.0 MB
     www/model/           7.6 MB
     ------------------------------
     합계 약              44 MB    ← 앱 크기로는 평범합니다

  [앱이 되면 새로 되는 것]
     · 인터넷 0 으로 전부 동작
     · 기압계로 층 알아내기
     · 카메라가 더 안정적 (특히 아이폰)
     · 24MB 다운로드가 사라져 켜자마자 뜸


5. 구조를 하나 바꿔야 합니다 (상의 필요)
────────────────────────────────────────────────────────────────

  지금까지 "index.html 한 파일이 전부" 를 원칙으로 지켜 왔습니다.
  깃허브 페이지에 파일 하나만 덮어쓰면 끝이라 편했기 때문입니다.
  (그리고 예전에 여러 파일로 나눴다가 사고가 난 적도 있습니다)

  그런데 앱으로 가면 이 원칙이 오히려 불편해집니다.

     · 사진을 더 넣을 때마다 24MB 짜리 파일을 통째로 다시 만들어야 함
     · 지금 24.2MB 인데 깃허브 웹 업로드 한계가 25MB — 여유가 거의 없음
     · 1층·2층 사진을 넣으면 넘습니다

  제안 : 기준 벡터(4.5MB)만 index.html 밖으로 빼서
         www/aivec.json 으로 두는 것.
     · index.html 은 20MB 로 줄어 여유가 생깁니다
     · 사진이 늘어도 aivec.json 만 바꾸면 됩니다
     · 앱 안에서는 같은 폴더의 파일이라 인터넷과 무관합니다

  다만 이렇게 하면 "웹에서 index.html 하나만 덮어쓰기" 는
  더 이상 안 됩니다. 두 파일을 올려야 합니다.
  → 하실지 말지 정해 주시면 그대로 따르겠습니다.
