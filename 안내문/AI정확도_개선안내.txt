# 사진 판별 AI 정확도 개선 — 적용 안내 (v52)

**기준** v51 → `index.html` (v52, +0.47MB)
**해결한 문제** 2층 복도 사진을 올렸는데 전혀 다른 곳이 1등으로 나오던 것

---

## 1. 먼저 — 예전 정확도 86.7%는 잘못 잰 숫자였습니다

v44에서 "정확도 86.7%"라고 알려드렸는데, 그 측정에는 **호실 사진 45장만 들어가 있었습니다.** 복도·엘리베이터·계단은 표본에 한 장도 없었고, 사진 변형도 약했습니다(밝기·살짝 확대 정도).

그래서 이번에는 **133장 전부**에, 실제 제보에 가까운 변형 7가지(다른 각도·저녁 어둠·역광·가까이서·흔들림·색바램·기울임)를 적용해 **931건**으로 다시 쟀습니다.

| | 예전 측정 | 다시 잰 v51 |
|---|---|---|
| 표본 | 호실 45장 × 6변형 = 270건 | **133장 × 7변형 = 931건** |
| top-1 정확도 | 86.7% | **77.3%** |

즉 실제 성능은 처음부터 77%대였고, 특히 **호실이 72%**로 가장 약했습니다. 복도는 90%였는데도 틀릴 때 엉뚱한 층·엉뚱한 호실이 1등으로 나와 "전혀 안 맞는다"고 느껴진 것입니다.

## 2. 무엇이 문제였나

원인은 모델이 아니라 **기준사진을 한 시점으로만 기억하고 있었던 것**입니다.

- 기준사진 133장 각각을 **사진 전체 한 장** 그대로만 특징으로 저장 → 제보자가 **더 가까이서** 찍거나 **한쪽에 서서** 찍으면 같은 장소인데도 특징이 크게 달라집니다.
- 게다가 이 모델이 내놓는 1280개 숫자는 **몇 개의 큰 값이 유사도를 좌우**해서, 서로 다른 실내 공간이 전부 0.9쯤으로 비슷하게 나옵니다. (실제로 관계없는 두 사진의 유사도가 0.896입니다.) 그 상태에서는 1등이 사실상 운으로 정해집니다.

## 3. 고친 것

1. **기준벡터를 사진 1장당 3시점으로** — 원본 / 가운데 82% / 가운데 65%. 같은 곳을 다른 거리에서 찍어도 셋 중 하나가 맞습니다. (가장 큰 효과: +10.6%p)
2. **제곱근 정규화** — 큰 값을 눌러 그 장소만의 세부 차이가 유사도에 반영되게 합니다. (+1.8%p)
3. **제보 사진도 2시점으로 비교** — 원본과 가운데 확대 둘 다 대보고 잘 맞는 쪽을 씁니다. 폰에서 0.2초쯤 더 걸립니다. (+1.3%p)
4. **임계값 전부 재측정** — 자동 확정 기준을 유사도 0.75→0.72, 격차 0.04→0.03으로, '기존 사진과 동일' 기준을 0.98→0.99로.
5. **메모의 층을 힌트로** — 지금까지는 "3층 왼쪽 복도"처럼 위치를 정확히 쓴 메모만 반영됐습니다. 이제 **"2층 복도"처럼 층만 있어도** 그 층 후보를 위로 올립니다.
6. **확실하지 않으면 단정하지 않음** — 1등과 2등이 다른 층인데 격차가 작으면 "2층 (다만 4층일 가능성도 있음 — 격차 2%p)"처럼 알려주고, 불확실할 때는 후보를 3개 → **5개** 보여줘 관리자가 눌러서 바로 고를 수 있게 했습니다.
7. **AI가 배우는 사진도 2시점으로 기억** — 관리자가 승인·등록한 사진에도 같은 방식이 적용됩니다.

|---|---|---|
| top-1 정확도 | 74.6% | **90.7%** |
| 후보 3개 안에 정답 | 82.8% | **93.7%** |
| 호실 | 69.3% | **88.2%** |
| 복도 | 90.0% | **100%** |
| 엘리베이터 | 93.8% | **100%** |
| 출입문 · 지하 | 100% | **100%** |

| 그중 맞은 비율 | 95.7% | **99.5%** |

관계없는 사진(색 노이즈)은 여전히 반려됩니다(유사도 0.49 → 기준 0.65 미만).

## 5. 올리고 확인하기

1. `index.html` 덮어쓰기 → `?v=52`로 열기
2. **2층 복도**를 다시 찍어 건의함에 올려보기 → 위치가 맞게 나오는지
3. 메모에 **"2층 복도"**만 적고 올려보기 → 층 힌트가 반영되는지
4. 관리자 화면에서 추정 위치·후보 버튼이 뜨는지, 눌러서 코드가 채워지는지

파일이 0.47MB 커졌지만(17.2 → 17.7MB), 렉 측정은 v51과 같았습니다(첫 화면 61프레임/초, 긴 작업 0건).

## 6. 확인한 것

- 실제 앱 코드로 268건 판정 — 위 표
- 메모 층 힌트가 순위를 실제로 바꾸는지 : 4건 시험, 4건 모두 메모한 층의 후보가 1등으로
- 학습 : 새 장소를 가르치면 2시점으로 저장되고 다시 찾아짐 · **v51까지 저장된 학습 기록도 그대로 읽힘**
- 관리자 표시 : 불확실할 때 후보 5개, 층 불확실 안내 문구
- 회귀 : QR 29건 · 관리자 스크롤 · 7자리 로그인 · 서버 연동 · 렉 제거 전부 이상 없음
- v41 원본 → `apply_all.py` → v52 바이트 동일 (재적용 도구에 10단계로 포함)

## 7. 남은 한계

- 호실 88%는 **비슷하게 생긴 강의실**에서 주로 틀립니다(책상·칠판·빔프로젝터 배치가 같은 방들). 후보 3개 안에는 93.7% 들어오므로, 관리자가 후보 버튼으로 고르는 것이 가장 빠릅니다.
- 더 올리려면 ① 방마다 **각도가 다른 사진을 2~3장씩** 앱에 등록하거나(가장 효과 큼, 파일만 커짐), ② 더 큰 모델(alpha 1.0)을 쓰는 방법이 있습니다. ②는 모델 내려받기가 7.6MB → 14MB로 늘어 건의함을 처음 여는 사람이 기다리게 됩니다.
- 기준사진을 바꾸면 기준벡터를 다시 계산해야 합니다. 방법은 도구 zip 안 `README.md`의 '사진이 바뀌었으면'에 적어 두었습니다.
