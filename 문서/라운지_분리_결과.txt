층별 라운지를 새 장소로 만들었습니다 (v72 · v73)            2026-09-21


■ 왜 했나

관리자 건의함에서 라운지를 제보하면 "엘리베이터 앞"으로 잡혔습니다.
원인은 사진 쪽이었습니다.

  사진원본\EV1 ~ EV5 (이름은 "엘리베이터 앞") 안에 있던 사진 217장 중
  엘리베이터 문이 아예 보이지 않는 라운지·로비 사진이 179장이었습니다.

AI 는 폴더 이름을 정답으로 배웁니다. 그래서 라운지 사진 179장이 전부
"엘리베이터 앞"이라는 이름표를 달고 있었고, 라운지를 찍어 제보하면
당연히 "엘리베이터 앞"이라고 답했습니다. 앱이 틀린 게 아니라
가르친 내용이 틀려 있었습니다.


■ 어떻게 나눴나

기준은 하나입니다.

  엘리베이터 문이나 호출버튼이 사진의 주인공인가?
     그렇다  → EV#   (엘리베이터 앞)
     아니다  → LNG#  (라운지. 단 1층은 로비)

217장을 전부 한 장씩 눈으로 보고 갈랐습니다.
애매한 18장은 따로 크게 키워 다시 확인했습니다.

  ┌──────┬──────┬───────┬────────┐
  │ 층   │ EV#  │ LNG#  │ EVIN#  │
  ├──────┼──────┼───────┼────────┤
  │ 1층  │   6  │   48  │   +1   │
  │ 2층  │   8  │   31  │   +1   │
  │ 3층  │   9  │   36  │   +1   │
  │ 4층  │   7  │   36  │   +1   │
  │ 5층  │   3  │   28  │   +1   │
  ├──────┼──────┼───────┼────────┤
  │ 합계 │  33  │  179  │   +5   │
  └──────┴──────┴───────┴────────┘

EVIN# 은 "엘리베이터 안"입니다. 각 EV 폴더에 한 장씩 엘리베이터 안에서
찍은 사진이 섞여 있어서 제자리로 옮겼습니다. 기존 EVIN 사진과 겹치지 않는
새 사진이라 기준이 5장 늘었습니다.


■ 층마다 라운지가 어떻게 생겼나 (사진을 보고 확인한 것)

  1층  로비   — 안내실 카운터, 게시판, 정문 유리문, 복사기·자판기
                "라운지"라는 말이 어울리지 않아 앱에서도 '1층 로비'로 부릅니다.
  2층  라운지 — R+ Cafe. 긴 책상과 의자, 파란 사물함, 나무 칸막이. 5개 층 중
                유일하게 앉아 쉬는 공간다운 곳입니다.
  3층  라운지 — 파란 사물함이 길게 늘어선 넓은 홀, 자판기, 창가
  4층  라운지 — 노란 사물함이 길게 늘어선 넓은 홀, 정수기, 게시판
  5층  라운지 — 4층과 거의 같은 모양 (노란 사물함 + 창가)
  지하 — 라운지가 없습니다. EVB1 13장은 전부 엘리베이터라서 그대로 뒀습니다.

3·4·5층이 서로 닮은 것은 AI 에게 어려운 조건입니다. 층을 가르는 단서는
사물함 색과 게시판 내용뿐이라, 층을 틀리면 대개 이 세 층끼리 틀립니다.


■ 앱에서 바꾼 것 (v72, 다섯 군데)

  1. 건의함 접수 범위에 LNG1~LNG5 를 넣었습니다.
     안 넣으면 AI 가 라운지로 판별하는 순간 "범위 밖"이라며 제보를 거절합니다.
     (v65 에서 EVIN·SIGN·EMS·WIN 이 빠져 있어 실제로 났던 사고입니다)
  2. 사람이 읽는 이름 : 'N층 라운지', 1층만 '1층 로비'
  3. 몇 층인지 계산할 때 LNG 를 알아보게
  4. 라운지는 호실이 아니라 열린 공간이므로, 복도와 같은 규칙으로 취급합니다.
     (멀리 찍힌 호실 번호판을 그 사진의 위치로 삼지 않습니다)
  5. 관리자가 메모에 'LNG3' 이라고 적어도 알아듣게

■ 만들면서 찾은 오류 세 가지 (전부 실제로 띄워 보고 찾았습니다)

  1. 함수 이름이 겹쳐 기능이 통째로 죽어 있었다
     새로 만든 sugFloorPick 이 학생용 화면의 변수 sugFloorPick 과 이름이 같아서,
     함수가 빈 문자열로 덮어써졌습니다. 화면은 멀쩡히 그려지는데 층을 골라도
     아무 일이 일어나지 않습니다. sugPickFloor 로 바꿨습니다.

  2. 고를 수 있는 장소에 8곳이 빠져 있었다
     창밖(WIN2~WIN5R) · 지하 엘리베이터(EVB1) · 동문 · 서문.
     목록을 만드는 함수가 SUGAI.libAll() 에 기대고 있었는데, 그 함수는 AI 기준
     데이터를 아직 안 읽었을 때 0개를 돌려줍니다. AI 는 "3층 창밖"이라고 답하는데
     관리자는 그 장소를 고를 수 없는 상태였습니다.
     → 기준벡터(AIVEC_DATA.codes)를 직접 읽도록 바꿨습니다. 이게 'AI 가 아는 장소'의
       유일한 정답지라, 앞으로 사진 폴더를 새로 만들어도 저절로 목록에 들어옵니다.

  3. 같은 문이 두 이름으로 들어 있었다
     동문이 GATE_E 와 GATE_EAST 로 각각 있어서 목록에 "동문"이 두 번 나왔습니다.
     사진이 실제로 붙는 쪽은 GATE_EAST 라, 짧은 쪽을 고르면 승인해도 안내 화면은
     그대로입니다 — 아무 표시 없이 실패합니다. 긴 쪽만 목록에 남겼습니다.
     지하 엘리베이터가 '기타'로 빠지던 것도 같이 고쳤습니다.

■ 확인한 것

  · 층 8개 모두에서 목록이 뜬다. '기타'로 빠지는 장소 0곳
  · AI 가 아는 장소 152곳이 전부 목록에 있다 (빠진 것 0)
  · AI 후보 버튼 → "✔ 4층 좌측 복도 (HALL4L)"
  · 라운지 버튼   → "✔ 2층 라운지 (LNG2)"
  · 직접 입력     → "✔ 13210호 (13210)"
  · 모르는 코드   → "※ 앱에 없던 새 위치 「ZZZ9」로 넣습니다"
  · 빈칸          → "아직 고르지 않았습니다"

  승인 로직(sugApprove)은 예전 그대로 코드 칸을 읽습니다 — 건드리지 않았습니다.
