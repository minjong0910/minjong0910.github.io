# 서버(Firestore) 연동 — 적용 안내 (v49)

**기준** v48 → `gunsan_b3nav_DB_v49.html` (+16KB)
**해결한 문제** 건의함 제보가 제보자 폰에만 남고 관리자에게 안 보이던 것

---

## 1. 이제 어떻게 동작하나

```
상대방 폰 ── 제보 ──▶ Firestore (구글 클라우드) ◀── 실시간 ── 관리자 폰·PC (여러 대 가능)
                          │
                          └── 승인된 사진 ──▶ 앱을 여는 모든 사람에게 자동 반영
```

| 기능 | 이전 (v48) | 지금 (v49) |
|---|---|---|
| 제보 저장 | 제보자 폰에만 | **서버** — 어느 관리자 기기에서도 보임 |
| 관리자 목록 | 새로고침해도 자기 폰 것만 | **실시간** — 제보 올라오면 즉시 뜸 |
| 승인·거절 | 자기 폰에만 기록 | 서버에 기록, 다른 관리자 화면에서도 사라짐 |
| 승인된 사진 | 파일 재배포해야 남들이 봄 | **자동 배포** — 다음에 앱 여는 사람부터 반영 |
| 관리자 진입 | 코드에 박힌 숫자 비밀번호 | **이메일 로그인** (웹에서) |
| 인터넷 끊김 | — | 제보를 폰에 두었다가 연결되면 자동 전송 |

**파일로 직접 열었을 때(개발 모드)** 는 예전처럼 동작합니다 — 서버 안 쓰고, 숫자 비밀번호로 진입. 3D 작업하면서 로컬에서 테스트하는 데 지장 없습니다.

---

## 2. ⚠️ 올리기 전에 꼭 — 보안 규칙 붙여넣기

Firestore를 「테스트 모드」로 만들면 **30일 뒤 모든 접근이 막히고**, 그 전까지는 **누구나 제보를 읽고 지울 수 있습니다.** 아래 규칙으로 바꿔야 합니다.

1. [console.firebase.google.com](https://console.firebase.google.com) → 프로젝트 `minjong-b974c`
2. 왼쪽 **빌드 → Firestore Database** → 위쪽 탭 **규칙**
3. 내용을 전부 지우고 아래를 붙여넣기 → **게시**

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // 제보 : 누구나 올릴 수 있지만, 읽기·승인·삭제는 로그인한 관리자만
    match /suggestions/{id} {
      allow create: if request.resource.data.status == 'pending'
                    && request.resource.data.u is string
                    && request.resource.data.u.size() < 950000
                    && request.resource.data.u.matches('data:image/.*');
      allow read, update, delete: if request.auth != null;
    }

    // 승인된 사진 : 누구나 볼 수 있고, 올리기·수정은 관리자만
    match /photos/{id} {
      allow read: if true;
      allow create, update, delete: if request.auth != null;
    }
  }
}
```

이 규칙이 하는 일 — 제보는 `status`가 `pending`이고 사진(950KB 미만)이 들어있을 때만 생성 가능. 그 외 모든 읽기·변경은 관리자 로그인 필요. 사진 컬렉션은 공개 읽기(앱이 내려받아야 하므로).

## 3. 관리자 계정 확인

아직 안 했다면:

1. Firebase 콘솔 → **빌드 → Authentication** → **시작하기**
2. **로그인 방법** 탭 → **이메일/비밀번호** → 사용 설정 → 저장
3. **Users** 탭 → **사용자 추가** → 이메일·비밀번호 입력 (이게 관리자 계정)

팀원 것도 만들면 각자 폰에서 같은 목록을 봅니다.

1. `index.html` 덮어쓰기 → `?v=49`로 열기
2. **폰 A**(아무나): 건의함 → 사진 제보 → 아래에 **「✓ 서버에 전송됨」** 확인
3. **폰 B**(관리자): 로고 5번 탭 → **이메일 로그인** → 사진 등록 → 건의함 검토 → 방금 제보가 떠 있고 상태줄에 **「● 실시간 연결 · 대기 1건」**

## 5. 확인한 것

**실제 프로젝트 연결** — REST로 `suggestions`에 문서 쓰기·읽기·삭제 성공 (config 정상).

**앱 흐름 검증 (모의 서버, 12개 시나리오 통과)**

- 제보 → 서버 저장, `fid` 부여, 전송 안내
- 웹 모드에서 이메일 로그인 폼 / 틀린 비밀번호 오류 / 성공 시 진입
- 관리자 화면: 서버 목록 실시간 표시, 상태줄, 로그아웃 버튼, AI 자동입력 유지
- **다른 기기에서 올린 제보가 실시간으로 추가됨**
- 승인 → 서버 `approved` + `photos` 배포 + 목록에서 제거 + 이 기기 사진 반영
- 거절 → 서버 `rejected`
- 새 기기가 앱을 열면 승인 사진 내려받아 병합 (중복 방지)
- 인터넷 없을 때 → 폰에 보관 → 복구 시 자동 재전송
- 파일로 열면 개발 모드 (숫자 비밀번호, 서버 안 씀)
- QR 회귀 없음

**설계 결정**

- Firestore를 브라우저에서 직접 씁니다. 파이썬 서버 없이도 이 문제는 해결되고, 카드 등록이 필요 없습니다.
- 사진은 Storage 대신 Firestore 문서에 넣습니다(문서당 1MB 한도 → 900KB 넘으면 자동 축소). Storage는 카드 등록이 필요해서 피했습니다.
- SDK는 건의함·관리자 화면에 들어갈 때만 내려받습니다. 길안내만 쓰는 사람은 영향 없습니다.
- `where(status=='pending')`만 쓰고 정렬은 앱에서 합니다 — Firestore 복합 색인을 안 만들어도 되게.

## 6. 한계와 다음

- 승인된 사진의 AI 기준벡터는 **승인한 기기**에서만 학습됩니다. 다른 사용자 기기의 AI는 그 사진을 모릅니다. 벡터도 서버에 올리면 해결되는데, 그건 파이썬 서버(설계서 원안)를 붙일 때 같이 하면 됩니다.
- 무료 한도: 하루 쓰기 2만·읽기 5만. 발표·시연 규모에서는 문제없습니다.
- 앱 시작 3초 뒤 승인 사진을 한 번 내려받습니다(사진 수만큼 읽기 소모). 사진이 수백 장 쌓이면 "최근 N장"만 받도록 바꾸면 됩니다.
