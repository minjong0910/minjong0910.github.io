3. 데이터 모델 · 계약
────────────────────────────────────────────────────────────────

  서버 API 가 없고 앱이 Firestore 에 직접 읽고 쓰므로, 아래 표와 서버/firestore.rules 가 곧 계약이다.
  규칙을 바꾸면 GitHub 의 서버 규칙 시험(tests/rules, 40가지)이 실제 요청으로 확인한다.

  admins/{uid}            관리자 명단                    읽기 : 자기 문서만        쓰기 : 불가(콘솔에서만)
  suggestions/{익명UID_날짜_번호}  제보
      u     사진 — data:image/(jpeg|png|webp);base64,…  · 950,000자 미만
      note  메모 ≤500자 · ts 시각(숫자) · status 반드시 'pending'
      ai    AI 결과 map(칸 60개 이하) 또는 null · qr  MAIN|BACK|EAST|WEST 또는 null
      ua ≤120 · cid ≤60 · uid ≤128(= 로그인한 익명 UID) · day ≤12(= 오늘 한국 날짜)
                                 읽기 · 승인 · 삭제 : 관리자   만들기 : 익명 로그인 폰이 하루 3번까지(관리자는 제한 없음)
  quota/{익명UID_날짜}    오늘 올린 횟수 n (1~3)         읽기 : 자기 것(오늘)만     만들 때 n=1, 올릴 때 +1 만(줄이기 · 삭제 불가)
  photos/{id}             승인된 사진
      code(장소 코드 ≤40, 영문 · 숫자 · _ -) · n 파일 이름 ≤200 · u 사진(제보와 같은 모양) · cap 설명 ≤600 ·
      sub ≤40 · sid 원래 제보 번호 ≤160 · ts · hide(숨김 기록일 때 true, 그때는 u 없음)
                                 읽기 : 누구나              쓰기 : 관리자(모양 검사)
  adminlog/{id}           관리자 작업 기록 (2026-11-10)
      act(approve · reject · status · delete_sug · publish · unpublish · hide · unhide ·
          자동 정리 auto_rejected · auto_old_pending · auto_approved) · target ≤160 · code ≤40 ·
      by(= 남긴 관리자 UID) · ts
                                 읽기 · 남기기 : 관리자     고치기 · 지우기 : 불가
  rooms/{key ≤20}         고친 방 정보 no ≤10 · name ≤40 · en ≤60 · memo ≤80 · show(map) · ts
                                 읽기 : 누구나              쓰기 : 관리자
  roomlog/{id}            방 정보 수정 기록             읽기 · 남기기 : 관리자     고치기 · 지우기 : 불가
  live/{행사}             발표장 접속 수 n · t           읽기 : 누구나              만들 때 n=1, 올릴 때 +1 (삭제 불가)
  live/{행사}/here/{16자} 지금 켜 둔 사람의 시각 t        읽기 : 누구나              시각만 쓰기 · 지우기

4. 배포
────────────────────────────────────────────────────────────────

  main 에 push → GitHub Actions(.github/workflows/check-and-deploy.yml)
      검사(test, Windows)    : 검사.ps1 -Ci — 파일 · 앱 · 설치 · 안전망 (글꼴 · 그래픽이 달라 글자 폭 · 3D 그림 비교만 뺌)
      서버 규칙 시험(rules)   : tests/rules — Firestore 에뮬레이터에 실제 요청 40가지
      배포(deploy)           : 검사를 통과해야만 site/ 를 GitHub Pages 로
      배포 뒤 확인(smoke)     : 사이트의 sw.js 판 = 방금 올린 판 · 주요 주소 7곳 200

  상황                              일어나는 일
  main 에 push                      검사 · 규칙 시험 → 통과하면 배포 → 배포 뒤 확인
  Actions 탭 → Run workflow (main)  같은 순서 — 커밋 없이 다시 배포할 때
  pull request                      검사 · 규칙 시험만 (PR 번호별 줄 — 배포 줄을 막지 않는다)
  매주 월요일 03:00 (한국)          전체 검사(-Full, 로드뷰 · 폰 경로까지)만 — 고치지 않아도 깨지는 것(브라우저 · 외부 주소)을 찾으려고
  검사 실패                         사이트는 그대로. Actions 탭에서 단계별 로그, server-log(서버 기록) 7일 보관

  ※ 배포는 검사와 서버 규칙 시험을 둘 다 통과해야 한다(needs: [test, rules] — 2026-11-10 규칙 시험이 GitHub 에서
    처음 40 / 40 으로 통과한 것을 확인하고 넣음).
  ※ 저장소 설정 → Pages → Source 는 「GitHub Actions」여야 한다.
  ※ 액션 버전 올림 알림은 .github/dependabot.yml (매주 · 규칙 시험 패키지는 매달).

  site/ 를 고쳤을 때 순서
    1. pwsh -File 도구\오프라인목록.ps1        폰에 저장되는 파일 목록(sw.js)을 새로 쓴다
    2. pwsh -File 도구\구조도_줄수_맞추기.ps1   구조도의 줄 수 · 소스를 맞춘다
    3. 검사_실행.bat (큰 변경이면 pwsh -File 검사.ps1 -Full)
    4. 화면을 일부러 바꿨다면 안전망 새 기준 :
         pwsh -File tests\run_golden.ps1 -Mode capture -Tag v176   (지금 기준 v175 의 다음 번호)
       그다음 검사.ps1 · tests\run_golden.ps1 의 기본 -Tag 를 같은 번호로. 의도하지 않은 변화면 기준을 바꾸지 말고 원인을 고친다.
    5. commit · push → Actions 초록 확인 → 사이트에서 직접 열어 확인
  서버/firestore.rules 를 고쳤으면 : 서버/규칙_붙여넣기용.txt 도 같게(검사가 확인) → 콘솔에 붙여 넣고 게시 →
    규칙 머리말 「마지막으로 콘솔에 게시한 날」을 고쳐 커밋.


5. 롤백 (문제가 생긴 배포를 되돌릴 때)
────────────────────────────────────────────────────────────────

  1. 문제가 된 커밋을 되돌린다 :  git revert <커밋>  → push → 검사 통과 후 자동 배포 (가장 안전 — 기록이 남는다)
  2. 발표용 안정판으로 통째로 돌아가야 하면 : 태그(예 v171)의 site/ 를 꺼내 새 커밋으로 올린다
       git checkout v171 -- site   → 검사 → commit → push
  3. 배포 줄이 멈췄으면(사례 3) Actions 탭에서 멈춘 실행을 Cancel 한 뒤 다시 실행.
     오래된 실행을 Re-run 하면 그 옛 커밋의 사이트가 배포된다 — 사례 5(사이트가 한 달 전 판으로 돌아감)가 바로 이것이다.
  4. 이미 앱을 설치한 폰은 앱을 켜면 알아서 새 판으로 바뀐다(sw.js · pwa.js). 옛 판이 계속 보이면 앱을 완전히 닫았다 다시 연다.
  5. 사이트가 정말 바뀌었는지 : https://minjong0910.github.io/sw.js 의 VERSION = 저장소 site/sw.js 의 VERSION
     (배포 뒤 확인 job 이 자동으로 본다).


6. Firebase 복구 (프로젝트를 새로 만들거나 설정이 사라졌을 때)
────────────────────────────────────────────────────────────────

  1. Authentication → 로그인 방법 → 「익명」 사용 설정(먼저), 「이메일/비밀번호」 사용 설정(관리자 로그인 —
     앱은 signInWithEmailAndPassword 를 쓴다, sugdb.js)
  2. Firestore Database 만들기 → 규칙 → 서버/규칙_붙여넣기용.txt 를 통째로 붙여 넣고 [게시] → 규칙 머리말에 날짜
  3. 관리자 계정을 만들고 그 UID 로 admins/{UID} 문서를 추가 — 순서는 서버/보안_설정_안내.txt · 서버/하루3번_방정보_설정_안내.txt
  4. 앱의 Firebase 설정값을 새 프로젝트 것으로 바꾼다 — 쓰는 곳 4군데 :
       site/js/app/sugdb.js 의 CFG (apiKey · authDomain · projectId …)
       site/js/app/live.js 의 PROJ · KEY
       site/live/index.html · site/live/go.html (발표장 화면)
     그다음 4절 「배포」 순서대로 올린다. (도구/구조도_틀.html 에도 예시로 들어 있다 — 구조도를 다시 만들면 따라온다)
  5. 규칙 플레이그라운드로 시험(익명 제보 허용 · 관리자 읽기 · 그 밖 거부)
  6. 승인 사진 · 방 정보를 백업에서 되살린다(7절)


7. 백업
────────────────────────────────────────────────────────────────

  무엇을          photos(승인 사진) · rooms(고친 방 정보) — 모든 사용자 화면에 나가는 것.
                  suggestions 는 승인 전 대기분이라 30일이 지나면 지워진다(개인정보 처리방침) — 백업하지 않는다.
                  roomlog · adminlog 는 관리자만 읽는 기록 — 아래 「관리자만 읽는 것」.
  어떻게          pwsh -File 도구\서버_백업.ps1
                    → 생성물\백업\<날짜_시각>\ 에 photos.json · rooms.json · 사진 파일 · 목록.txt
                    (공개 읽기만 쓴다 — 로그인 · 비밀번호가 필요 없고, 서버에 아무것도 쓰지 않는다)
                  pwsh -File 도구\서버_백업.ps1 -Check
                    → 가장 최근 백업을 다시 읽어 사진마다 그림으로 열리는지 · 장수가 목록과 같은지 · 방 정보가 읽히는지 시험
                  생성물\ 은 저장소에 올라가지 않는다 — 백업 폴더를 USB · 클라우드 드라이브에 따로 옮겨 둔다.
  얼마나 자주     (제안 — 바꿔도 된다) 큰 수정 전 · 학기 시작 전 · 발표 전날, 그리고 관리자가 사진을 여러 장 승인한 날.
  시험 기록       2026-11-10 14:12 백업 → -Check 통과 : 승인 사진 7장(1.6MB) 모두 그림으로 열림 · 방 정보 0개(아직 고친 방 없음).
  되살리기        · 방 정보 : 관리자 화면 「구성 및 변경」에서 rooms.json 의 값대로 다시 고친다(그러면 roomlog 에도 남는다).
                  · 승인 사진 : 두 길 중 하나.

  관리자만 읽는 것 roomlog · adminlog · 대기 중 제보는 공개 읽기가 막혀 이 도구로 못 받는다.
                  Firebase 콘솔의 「가져오기/내보내기」는 요금제에 따라 쓸 수 없을 수 있다 【확인 : 지금 요금제(Spark 무료 / Blaze)】.
                  기록이 꼭 필요하면 콘솔 → Firestore → 컬렉션을 열어 화면으로 확인한다.
  사진 원본       2.9GB(사진원본/)는 저장소에 없다 — 보관 위치 · 담당은 문서/운영_인수인계.txt 1절.
  AI 기준 자료    사진 원본이 있으면 다시 만들 수 있다 : gen.html(약 7분) → 도구\AI자료_넣기.ps1 (README 「AI 자료 다시 만들기」).
