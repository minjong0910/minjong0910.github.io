## 1. 무엇이 생겼나

| `#sqr` (신규) | 카메라 프리뷰 + 스캔 프레임. 사진 인식·수동 선택 폴백 포함 |

**동작 흐름**

```
첫 화면 → QR 스캔 → 확인 화면(사진 대조) → 「네, 여기예요」

                              출발점 = 그 문 / 출발층 = 1층 자동 설정

                     '무엇을 찾으세요?' 화면으로 바로 이동

```

목적지 화면에는 **「⛶ 서문 출발」** 배지가 표시되고, 스캔 결과는 **3시간** 유지됩니다.

## 2. QR 인식 — 4단계 폴백

발표 중 어떤 상황에서도 막히지 않도록 4단계로 준비했습니다.

| 순위 | 방식 | 동작 환경 |
|---|---|---|
| 1 | `BarcodeDetector` | 안드로이드 크롬 — 브라우저 내장, 가장 빠름 |
| 2 | `jsQR` (파일에 내장) | 아이폰 사파리 등 나머지 전부 |
| 3 | **📷 사진으로 인식** | 카메라 권한이 막힌 환경 (아래 3장 참고) |
| 4 | **문 직접 선택 버튼** | 위 셋이 모두 안 될 때 |

---

## 2-1. 카메라 권한이 안 뜰 때

화면 맨 아래 작은 회색 글씨(예: `file · 권한 denied`)를 먼저 보세요. 원인이 거기 적혀 있습니다.

| 진단 줄 | 원인 | 해결 |
|---|---|---|
| `file · …` | HTML 파일을 직접 열었음 | 3장대로 웹 주소(https)에 올리기. 당장은 「📷 사진으로 QR 찍기」 사용 |
| `https · 권한 denied` | 예전에 **거부**를 눌러 브라우저가 기억함 | 화면에 뜬 해제 경로대로 바꾼 뒤 「↻ 카메라 다시 시도」 |
| `https · 권한 prompt` | 아직 동의 안 함 | 「↻ 카메라 다시 시도」 → **허용** |
| `https · 권한 granted` | 정상 | 바로 스캔됨 |

**브라우저별 권한 해제 경로** (앱이 알아서 맞는 것을 보여주지만, 미리 알아두면 편합니다)

| 브라우저 | 경로 |
|---|---|
| 안드로이드 크롬 | 주소창 왼쪽 **자물쇠** → 권한 → 카메라 → 허용 |
| 아이폰 사파리 | 주소창 왼쪽 **ᴀA** → 웹사이트 설정 → 카메라 → 허용 |
| 삼성 인터넷 | 주소창 왼쪽 **자물쇠** → 권한 → 카메라 → 허용 |

> **한 번 거부하면 동의창은 다시 안 뜹니다.** 브라우저 정책이라 코드로는 되돌릴 수 없습니다. 그래서 권한이 필요 없는 「📷 사진으로 QR 찍기」를 항상 큰 버튼으로 함께 띄워둡니다 — 폰 기본 카메라가 열리고, 찍으면 바로 인식됩니다.

## 3. ⚠️ 중요 — 카메라를 쓰려면 웹 주소로 올려야 합니다

브라우저는 **HTML 파일을 직접 연 상태(`file://`)에서는 카메라를 차단**합니다. 보안 정책이라 우회할 수 없습니다.

| 여는 방법 | 실시간 카메라 스캔 | 사진으로 인식 | 수동 선택 |
|---|---|---|---|
| 파일을 직접 열기 (카톡으로 받아서 열기 등) | ❌ | ✅ | ✅ |
| **웹 주소(https)로 열기** | ✅ | ✅ | ✅ |

**무료로 https 주소 만드는 법 (5분, 카드 불필요)**

가장 간단한 건 GitHub Pages입니다.

1. github.com 가입 → 새 저장소 생성 (Public)
2. `gunsan_b3nav_QR_v42.html`을 `index.html`로 이름 바꿔 업로드
3. 저장소 Settings → Pages → Source를 `main` 브랜치로 지정
4. 1~2분 뒤 `https://아이디.github.io/저장소이름/` 으로 접속 가능

> 파일이 16MB라 첫 로딩이 느립니다. 발표 전에 미리 한 번 열어두면 캐시가 남아 빨라집니다.
> 설계서의 서버 도입(사진 분리)을 하면 이 문제가 함께 해결됩니다.

**웹에 못 올리는 상황이면** — 파일로 열어도 「📷 사진으로 인식」이 동작하므로 시연은 가능합니다. QR을 폰 카메라로 찍기만 하면 됩니다.

## 4. QR 스티커 인쇄·부착

| 파일 | 용도 |
|---|---|
| `출입문QR_인쇄용_A4.pdf` | **A4 한 장에 4개 전부** — 이것만 인쇄하면 됩니다 |
| `QR_MAIN_정문.png` 외 3개 | 개별 이미지 (발표 자료·크게 인쇄용) |

**부착 방법**

1. A4로 인쇄 (일반 용지 가능, 두꺼운 종이 권장)
2. 점선 따라 자르고 코팅 또는 투명 테이프로 방수 처리
3. **각 문 안쪽**, 눈높이(바닥에서 약 150cm)에 부착

> 문 **안쪽**에 붙이는 이유 — 확인 화면에 '정문내부' 사진이 뜨는데, 스캔한 사람이 실제로 보는 장면과 같아야 "여기가 맞구나"를 바로 알 수 있습니다.

**QR 원문** (앱과 반드시 일치해야 함)

```
정문 : B3NAV1:BLD:MAIN
후문 : B3NAV1:BLD:BACK
동문 : B3NAV1:BLD:EAST
서문 : B3NAV1:BLD:WEST
```

오류정정 레벨 **H(30%)** 로 만들어서, 스티커의 30%가 훼손돼도 인식됩니다.

## 5. 확인한 것

**기능 테스트 29항목 전부 통과**

- QR 문자열 해석 — 순수 텍스트 / 소문자 / 공백 / 서명 포함 / URL 형식 / 무관한 QR 거부
- 실제 인쇄용 QR 이미지 4장을 앱의 jsQR로 디코딩 → 4/4 정확
- 확인 화면에 해당 문의 실제 사진이 뜨는지
- 확정 후 `startFloor` 반영, 카테고리 화면 이동, localStorage 저장
- 목적지를 열어도 출발층이 1층으로 초기화되지 않는지 (`openTarget` 패치 검증)
- 콘솔 오류 0건

**라이브 카메라 스캔 검증** — 가상 카메라에 동문 QR 영상을 실제로 재생시켜, 앱이 영상에서 QR을 잡아 확인 화면까지 가는 것과 인식 직후 카메라가 꺼지는 것까지 확인했습니다.

**권한 시나리오별 안내 검증** — 차단 저장 / 아직 미동의 / 카메라 없는 기기 / 다른 앱이 사용 중, 네 가지 모두 각기 다른 안내와 해결 버튼이 뜨는 것을 확인했습니다. 권한 요청이 사용자 클릭과 같은 시점에 나가는지도(`userActivation.isActive`) 확인했습니다.

## 6. 나중에 바꿀 때

**문마다 층이 다르면** — 3호관은 4개 문이 모두 1층 기준이지만, 실제로 다르면 `QRNAV` 모듈 상단만 고치면 됩니다.

```js
var GATES = {
  MAIN: {ko:'정문', en:'Front Gate', floor:1, sub:'정문내부'},
  BACK: {ko:'후문', en:'Back Gate',  floor:1, sub:'후문내부'},
  EAST: {ko:'동문', en:'East Gate',  floor:2, sub:'동문내부'},   // ← 2층이면 이렇게
  WEST: {ko:'서문', en:'West Gate',  floor:1, sub:'서문내부'}
};
```

**서버를 붙일 때** — `QRNAV.parse()`가 이미 URL 형식(`https://…/q/BLD.MAIN`)과 서명이 붙은 형식(`B3NAV1:BLD:MAIN:a7f3c1`)도 인식합니다. 서버가 생겨도 **지금 인쇄한 QR을 그대로 쓸 수 있습니다.**

## 7. 발표에서 쓸 만한 포인트

1. **"위치 인식에 4단계 폴백을 뒀습니다."** 실시간 카메라 → 사진 인식 → 수동 선택. 어느 환경에서도 기능이 죽지 않습니다.
2. **"인터넷 없이 동작합니다."** QR 문자열 자체에 위치가 들어 있어 서버 왕복이 필요 없습니다.
3. **"QR 규격을 서버 도입까지 고려해 설계했습니다."** 나중에 서버가 생겨도 스티커 재인쇄가 필요 없습니다.
4. **"오류정정 레벨 H를 썼습니다."** 실외 부착 환경에서 훼손·오염을 견디도록 30% 복원 가능한 규격을 선택했습니다.
