3D 성능 재는 법 (폰에서, 5분)
================================

왜 재나
  목적지 3D 화면은 한 프레임에 그리는 덩어리(드로우콜)가 폰 화면에서 약 740개다.
  파란 테두리 선을 층마다 한 덩어리로 합치면 345개로 줄고,
  이 PC(데스크톱)에서 한 프레임 그리는 시간이 10.3ms → 4.4ms 로 줄었다 (2026-09-21).
  폰은 PC보다 3~5배 느려서 실제로 얼마나 부드러워지는지는 폰에서 재야 안다.

  단점 : 그림이 완전히 같지는 않다. 테두리 선 위치는 똑같지만, 몇몇 선이 앞쪽 반투명
  상자 색에 살짝 물들어 조금 어둡거나 옅게 보인다. 그래서 기본값은 예전 그대로 두었다.

준비
  새 index.html 을 GitHub 에 올린 뒤에 한다 (주소 뒤에 붙이는 스위치는 새 파일에만 있다).

재는 순서 (한 폰에서 두 번)
  1) 폰 브라우저 주소창에  https://minjong0910.github.io/?perf=1
     → 아무 강의실이나 검색해서 목적지 3D 화면까지 간다 (예 : 13310)
     → 화면 왼쪽 위 검은 칸의 숫자를 10초쯤 본 뒤 적는다
          fps   : 1초에 그린 장면 수. 폰은 30 이 최대다 (배터리 때문에 30으로 묶어 둠)
          calls : 드로우콜
          ms    : 한 장면 그리는 데 든 시간. 33 을 넘으면 30fps 를 못 낸다
  2) 주소를  https://minjong0910.github.io/?perf=1&merge=1  로 바꿔 같은 강의실로 1) 을 반복
     → 왼쪽 위에 "merge ON" 이 보이면 합치기가 켜진 것
  3) 두 화면을 눈으로도 비교한다 — 테두리 선이 거슬리게 달라 보이는지

적을 표
  폰 이름      | 스위치   | fps | calls | ms | 모양 괜찮나
  iPhone 14    | 없음     |     |       |    |
  iPhone 14    | merge=1  |     |       |    |
  Galaxy S20   | 없음     |     |       |    |
  Galaxy S20   | merge=1  |     |       |    |

판단
  · merge=1 에서 fps 가 눈에 띄게 오르고(예 : 20 → 30) 모양도 괜찮으면 → 켜 달라고 하면 된다
    (index.html 의 edgeMergeOn() 이 늘 true 를 돌려주게 바꾸는 한 줄 수정)
  · 둘 다 이미 30 이면 → 폰이 충분히 빠른 것. 그대로 둬도 된다
  · 모양이 거슬리면 → 켜지 않는다

참고
  · ?perf=1 은 재는 동안만 쓰는 스위치다. 일반 사용자 주소에는 붙이지 않는다.
  · 층 상세 화면과 실사 3D 는 이 스위치와 상관없다.
  · 걷기(직접 걸어보기) 중에는 원래 테두리 선을 모두 숨기므로 두 경우가 똑같다.
