# 건의함 사진 판별 AI — 적용 안내 (v44)

**기준** `gunsan_b3nav_QR_v43.html` → `gunsan_b3nav_AI_v44.html`
**추가 용량** +0.25MB (16.66MB → 16.92MB)
**서버 필요 여부** 없음 — 브라우저 안에서 직접 판별

---

## 1. 무엇이 생겼나

건의함에 사진을 올리면 **AI가 먼저 확인한 뒤** 관리자에게 넘어갑니다.

```
사용자가 사진 제출
      │
      ▼
1단계 · 품질검사  (순수 JavaScript, 인터넷 없이 동작)
   흔들림 · 밝기 · 해상도
      │ 불합격 → 이유를 알려주고 즉시 반려 (관리자에게 안 감)
      ▼ 합격
2단계 · 위치 판별  (MobileNetV2, 브라우저에서 실행)
   사진 → 1280차원 특징벡터 → 기준사진 133장과 코사인 유사도 비교
      │
      ├─ 유사도 < 60%        → 건물과 무관한 사진, 자동 반려
      ├─ 60~75% 또는 격차 작음 → 접수하되 "위치 불확실" + 후보 3개 제시
      ├─ 75% 이상 & 격차 4%p+ → 위치 자동 확정
      └─ 98% 이상            → 기존 사진과 거의 동일 (안내 후 접수)
      │
      ▼
관리자 화면 : AI 배지 + 위치 코드 자동 입력 + 후보 버튼
      │
      ▼
최종 승인은 사람이 — AI는 관리자의 입력을 대신 채워줄 뿐
```

**학습 데이터를 따로 모으지 않았습니다.** 앱에 이미 들어있는 기준사진 133장이 그대로 정답표 역할을 합니다. 사진을 추가하면 인식 범위도 함께 넓어집니다.

## 2. 측정 결과

사진 45장에 **촬영 변화 6종**(밝게·어둡게·확대·이동·채도·기울임)을 적용한 **270건**으로 측정했습니다.

| 항목 | 결과 |
|---|---|
| 위치 맞힘 (top-1) | **86.7%** |
| 정답이 후보 3개 안에 포함 | **94.4%** |
| 무관한 사진 자동 반려 | **100%** (실제 사진 오반려 0%) |
| 자동확정 조건일 때 정답률 | **98.5%** (전체의 76%가 자동확정) |

**촬영 변화별 정확도**

| 변화 | 정확도 |
|---|---|
| 채도 변화 | 100% |
| 심한 저조도 | 97.8% |
| 어둡게 + 화각 이동 | 95.6% |
| 밝게 + 확대 | 82.2% |
| 기울여 촬영 | 80.0% |
| 심하게 확대(70%) | 64.4% |

### 저조도 문제를 어떻게 해결했나 (발표용 포인트)

처음 측정했을 때 **어두운 사진의 정확도가 15.6%로 무너졌습니다.** 같은 장소라도 조명이 다르면 완전히 다른 사진이 되기 때문입니다.

그래서 모델에 넣기 전에 **밝기 히스토그램의 2~98% 구간을 0~255로 펴는 정규화**를 넣었습니다. 기준사진과 제보사진에 똑같이 적용합니다.

| | 정규화 전 | 정규화 후 |
|---|---|---|
| 저조도 사진 | 15.6% | **97.8%** |
| 전체 정확도 | 71.5% | **86.7%** |

한 줄짜리 전처리로 전체 정확도가 15%p 올랐습니다. 발표에서 "문제를 측정하고 원인을 찾아 해결했다"는 근거로 쓰기 좋습니다.

## 3. 임계값을 이렇게 정한 이유

전부 실측 분포에서 나왔습니다. 추측한 숫자가 없습니다.

```
무관한 사진 최고 유사도    0.420
                          ↑ 이 구간이 비어 있다
반려 임계값 TH.RELEVANT   0.600
                          ↓
실제 사진 최저 유사도      0.679
```

이 간격 덕분에 **무관한 사진은 100% 걸러내면서 실제 사진은 하나도 잘못 반려하지 않습니다.**

자동확정 조건(유사도 75% 이상 **그리고** 1등·2등 격차 4%p 이상)은 아래 표에서 골랐습니다.

| 조건 | 자동확정 비율 | 그중 정답률 |
|---|---|---|
| 유사도 75%, 격차 2%p | 86% | 95.7% |
| **유사도 75%, 격차 4%p** | **76%** | **98.5%** |
| 유사도 85%, 격차 6%p | 59% | 100% |

> 격차(margin)를 함께 보는 게 핵심입니다. 비슷한 강의실이 여러 개라 1등만 봐서는 확신할 수 없지만, 1등이 2등을 확실히 앞서면 믿을 수 있습니다.

## 4. 모델 선택 — 왜 작은 모델인가

MobileNetV2를 alpha 0.50과 1.00 두 가지로 같은 조건에서 비교했습니다.

| | alpha 0.50 | alpha 1.00 |
|---|---|---|
| 정확도 | 88.8% | 88.8% |
| 다운로드 | **7.6MB** | 13.3MB |
| 추론 속도 | **2배 빠름** | 기준 |
| 무관한 사진 최고 유사도 | **0.481** (구분 잘 됨) | 0.563 |

정확도가 같은데 용량은 절반, 속도는 두 배, 무관한 사진 구분도 더 좋아서 **alpha 0.50**을 선택했습니다.

## 5. 아이폰 대응 (PHFIX)

아이폰 기본 촬영 포맷인 **HEIC**는 사파리는 읽지만 안드로이드 크롬은 못 읽습니다. 기존에는 이때 "사진을 처리하지 못했어요" 한 줄만 떴습니다.

| 항목 | 이전 | v44 |
|---|---|---|
| 형식 판별 | 확장자만 믿음 | 파일 앞부분(매직 넘버)으로 **실제 형식** 확인 |
| HEIC | 무조건 실패 | 사파리는 그대로 처리, 안 되면 **자동 변환** |
| 읽기 시도 | 2단계 | **3단계** (createImageBitmap → blob URL → FileReader) |
| 큰 사진 | 처리 중 오류 | 아이폰 캔버스 한계(1,670만 픽셀)에 맞춰 자동 축소 |
| 오류 안내 | 한 줄 | **원인별 안내** (동영상 / 손상 / 빈 파일 / 너무 큼 / HEIC) |

형식 판별은 JPEG · PNG · GIF · BMP · WEBP · HEIC · AVIF · 동영상 · 빈 파일 9종을 구분하는 것까지 테스트로 확인했습니다.

## 6. QR과의 연계

QR을 찍고 제보하면 관리자 화면에 **「⛶ MAIN QR 스캔 후 제보」** 표시가 함께 뜹니다. 어느 문에서 올린 제보인지 알 수 있어 관리자가 판단하기 쉬워집니다.

## 7. (선택) 추가 파일 올리기 — 더 빠르고 확실하게

`b3nav_AI_추가파일.zip` 안에 두 폴더가 있습니다.

| 폴더 | 내용 | 크기 |
|---|---|---|
| `model/` | AI 모델 | 7.6MB |
| `lib/` | TensorFlow.js 라이브러리 | 1.5MB |

**올리지 않아도 앱은 정상 동작합니다.** 그 경우 AI가 필요할 때 인터넷에서 자동으로 내려받습니다. 다만 올려두면:

- 학교 와이파이가 외부 CDN을 막아도 AI가 동작
- 첫 실행이 더 빠름
- 외부 서비스가 바뀌어도 영향 없음 (발표 당일 사고 방지)

**올리는 방법**

1. ZIP 압축을 풀면 `model` 폴더와 `lib` 폴더가 나옵니다
2. 깃허브 저장소 → **Add file** → **Upload files**
3. 두 폴더를 통째로 끌어다 놓기
4. **Commit changes**

올린 뒤 저장소 파일 목록이 이렇게 보이면 성공입니다.

```
index.html
lib/
model/
```

## 8. 확인한 것

**자동 테스트 통과**

- 내장 기준벡터 133개 × 1280차원 정상 로드
- 모델 로드 → 예열 추론까지 완료
- 실제 기준사진 판별 → 위치 정확, `same` 판정
- 밝기·크롭을 바꾼 사진 10건 → **10/10 정확**
- 무관한 사진 → 자동 반려 (유사도 0.24)
- 흔들린 사진 / 새까만 사진 / 너무 작은 사진 → 각각 올바른 이유로 반려
- 파일 형식 판별 7종 전부 정확
- 제보 → 관리자 화면 AI 배지 + 위치 자동입력 + 후보 버튼 3개 + QR 표시
- QR 기능 29항목 회귀 없음
- 콘솔 오류 0건

**두 기기 호환성** — v44에서 새로 추가한 958줄에 화살표 함수·템플릿 리터럴·`let`/`const`·옵셔널 체이닝·`async/await`·`Promise.finally` 등 구형 브라우저에서 깨지는 문법이 **하나도 없습니다.** 전부 ES5 문법으로 작성했습니다.

## 9. 조절과 진단

**임계값 조절** — `SUGAI.TH` 에 모여 있습니다.

```js
SUGAI.TH.SHARP    = 45;     // 낮출수록 흔들린 사진을 관대하게 받음
SUGAI.TH.RELEVANT = 0.60;   // 정상 사진이 자꾸 반려되면 0.55로
SUGAI.TH.MATCH    = 0.75;   // 위치가 자꾸 틀리게 입력되면 0.85로
SUGAI.TH.MARGIN   = 0.04;   // 함께 올리면 더 보수적으로
```

**실제 사진으로 진단** — 개발자도구 콘솔에서:

```js
SUGAI.tune()     // 사진을 고르면 판정·품질·후보가 표로 출력
PHFIX.check()    // 사진 형식과 처리 실패 원인 확인
```

실제 휴대폰으로 찍은 사진 10~20장을 넣어보고 수치를 보면서 조절하세요.

## 10. 알아둘 한계

- **비슷하게 생긴 강의실은 헷갈릴 수 있습니다.** 그래서 자동 승인이 아니라 관리자 승인을 남겨두었고, 틀렸을 때를 대비해 후보 3개를 함께 보여줍니다.
- **심하게 확대해서 찍으면(70% 크롭) 64.4%로 떨어집니다.** 제보할 때 장소 전체가 보이게 찍어달라는 안내가 필요합니다.
- 낮/밤·계절 변화가 크면 유사도가 떨어집니다. 기준사진을 계절별로 여러 장 넣으면 개선됩니다.
- 인터넷이 완전히 끊기면 품질검사만 하고 위치 판별은 건너뜁니다 (앱은 정상 동작).
- **서버를 붙이면** 같은 파이프라인을 백엔드로 옮기고, 여러 사람의 제보를 모아 "같은 위치에 3명 이상이 같은 변화를 제보하면 자동 반영" 같은 규칙을 추가할 수 있습니다. 이게 자연스러운 다음 단계입니다.
