# 폰 렉 제거 — 적용 안내 (v51)

**기준** v50 → `index.html` (v51, +6KB)
**해결한 문제** 폰에서 첫 화면·목록·건의함까지 전부 버벅이던 것

---

## 1. 원인

앱을 켜는 순간부터 끝날 때까지, 어느 화면에 있든 **3D 엔진 두 개가 매 프레임 건물 전체를 그리고 있었다.**

| | 어디 | 언제 돌았나 |
|---|---|---|
| 목적지 3D (4번 화면) | `animate()` | 앱 시작 → 끝까지, 화면과 무관하게 |
| 건물 확인 3D (2번 화면, iframe) | iframe 안 `loop()` | 앱 시작 1.2초 뒤 → 끝까지, 안 보여도 회전·렌더 |

둘 다 드로우콜 수백 개짜리 장면이라, 첫 화면에서 버튼을 눌러도 GPU·CPU가 이미 꽉 차 있어서 터치 반응이 늦었다.
거기에 앱 시작 때 **16MB HTML 전체를 문자열로 복사**(개발용 '사진 담아 저장'에만 쓰는 것)하고, 길안내만 쓰는 사람 폰에도 **Firebase SDK 500KB**를 내려받고 있었다.

## 2. 고친 것

1. **목적지 3D 루프는 4번 화면이 보일 때만** — 다른 화면으로 가면 멈추고, 돌아오면 다시 켠다. (5번 화면의 층 상세 3D가 이미 쓰던 방식과 같음)
2. **건물 3D(iframe)도 2번 화면에서만** — iframe 안 코드는 손대지 않고, 부모가 그 창의 `requestAnimationFrame`을 감싸서 화면 밖이면 다음 프레임을 붙들어 둔다. 그래서 **3D 파일을 나중에 통째로 바꿔도 그대로 동작**한다.
3. **폰에서는 4번 화면 그리기를 초당 30장으로** — 사람 이동·회전 계산은 매 프레임 하고 그리기만 거른다(이동은 시간 기준이라 속도 그대로). 손가락 조작이 끼어들 여유가 생긴다.
4. **폰에서 건물 3D 해상도 배율 2 → 1.4** (목적지 3D와 같은 기준) — 픽셀 처리량 절반.
5. **앱이 백그라운드로 가면 3D 전부 정지**, 돌아오면 보고 있던 화면 것만 재개.
6. **안 보이는 화면의 CSS 애니메이션 정지** (스캔 레이저·배너 등).
7. **16MB 복사본은 웹에서 안 만든다** — '사진 담아 저장' 버튼을 누를 때 서버에서 원본을 내려받아 쓴다. 파일로 직접 연 개발 모드는 예전 그대로.
8. **승인 사진 내려받기를 REST 한 번으로** — 일반 사용자는 Firebase SDK를 받지 않는다. 건의함·관리자 화면에 들어갈 때만 받는다. (REST가 막히면 예전 SDK 경로로 자동 대체)
9. 건물 3D 미리 만들기 1.2초 → 2.5초 (첫 화면이 자리 잡은 뒤).

## 3. 측정 (중급 폰 흉내 : CPU 4배 느리게, 같은 조건)

| 화면 | v50 | v51 |
|---|---|---|
| 페이지 준비(DOMContentLoaded) | 7.7초 | **6.7초** |
| 첫 화면 프레임 | 1/초, 3.6~3.9초씩 멈춤 | **60/초, 멈춤 없음** |
| 카테고리 화면 | 1/초, 31초 멈춤 | **62/초, 멈춤 없음** |
| 3D에서 나온 뒤 첫 화면 | 2/초, 긴 작업 14건 | **62/초, 0건** |
| 메모리(JS) | 80MB | **45MB** |

4번 화면(목적지 3D) 자체는 원래 무거운 화면이라 그대로 GPU 성능에 좌우된다. 여기서 더 빠르게 하려면 3D 모델의 장식 메쉬 수(드로우콜 600~700)를 줄이는 것이 다음 단계다.

## 4. 올리고 확인하기

1. `index.html` 덮어쓰기 → `?v=51`로 열기
2. 첫 화면·카테고리·건의함에서 버튼 반응이 바로 오는지
3. 2번(건물 3D) → 나갔다 다시 들어오면 회전이 이어지는지
4. 4번(목적지 3D)에서 경로 재생·회전이 되는지, 나갔다 들어와도 되는지
5. 관리자 → 사진 등록 → '사진 담아 저장'이 되는지 (웹에서는 원본을 한 번 내려받느라 몇 초 걸림)

## 5. 확인한 것 (모의 서버, 전부 통과)

- 시작 시 두 3D 루프 모두 정지 · 웹에서는 16MB 복사본 없음
- 2번 화면 들어가면 건물 3D 렌더 시작, 나가면 0회, 다시 들어가면 이어서
- 4번 화면 들어가면 목적지 3D 렌더 시작, 나가면 0회, 되돌아오면 재개
- 백그라운드 → 정지, 복귀 → 재개 · 5번 화면 층 상세 루프 그대로
- 승인 사진 REST로 병합(pid·code·설명 변환), SDK 안 받음 · REST 실패 시 SDK 대체
- 7자리 로그인·잠금(v50) · QR 29개 · 관리자 스크롤(v48) 회귀 없음
- 파일로 열면(개발 모드) 예전처럼 즉시 복사본 유지
- v41 원본 → `apply_all.py` → v51 바이트 동일 (재적용 도구에 9단계로 포함)
