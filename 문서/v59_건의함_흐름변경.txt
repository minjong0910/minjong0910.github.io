 v59 — "어디에서 찍으셨나요?" 강제 선택 화면 제거

1. 왜 없앴나
----------------------------------------------------------------
 길을 잃어서 앱을 켠 사람에게 "여기가 어디인지 고르세요"라고 묻고 있었다.
 처음 온 사람은 건물 구조도, 호실 번호도 모른다.
 앱이 해야 할 일을 사용자에게 떠넘기는 화면이었다.


2. 흐름이 어떻게 바뀌었나
----------------------------------------------------------------
 예전
   사진 올림 -> AI 판별 -> 확신하면 접수
                        -> 아니면 [어디에서 찍으셨나요?] 화면 (강제)
                           사용자가 고름 -> 접수

 지금
   사진 올림 -> AI 판별 + 번호판 OCR
             -> 번호판을 읽었으면      : 그 호실로 바로 접수
             -> 못 읽었으면            : "위치 미정"으로 바로 접수
                                        관리자가 확정

 사용자는 어느 경우에도 아무것도 고르지 않는다. 사진만 올리면 끝이다.


3. 바꾼 곳 4군데
----------------------------------------------------------------
 (1) 번호판 OCR 결과를 확신으로 인정
     예전 코드는 OCR 로 호실을 읽어내도 확신으로 쳐주지 않고
     고르기 화면으로 보냈다(ai.codeSource !== 'ocr' 조건).
     실측에서 OCR 이 사진 판별보다 훨씬 정확했으므로, 읽혔으면 그게 답이다.

 (2) 제보 흐름에서 고르기 화면 호출 제거
     위치를 못 정하면 verdict='unknown' 으로 그냥 접수한다.

 (3) 접수 후 'AI가 정한 위치 바꾸기' 단추도 숨김
     같은 화면을 여는 단추라 함께 숨겼다.

 (4) 사용자 카드에서 유사도·후보 줄 숨김
     "유사도 43% · 다음 후보 13419" 같은 줄은 사용자에게 의미가 없다.
     관리자 화면에는 그대로 나온다.


4. 사용자가 보게 되는 것
----------------------------------------------------------------
 번호판을 읽은 경우
   ✅ 위치 확인 — 13205 사진으로 확인했어요
      관리자 화면에 위치가 자동으로 입력됩니다.

 못 읽은 경우
   📮 접수됨 — 사람이 직접 확인할 거예요
      제보가 정상 접수됐습니다.


5. 관리자는 무엇을 보나 (그대로다)
----------------------------------------------------------------
   [제보 사진]  메모 / 시각
                🤖 AI 판별 안 됨
                🔢 번호판 13205 → 2층 (이 방으로 확정)     <- 읽혔을 때
                [13419] [13405] [13409] [13204] [13303]   <- 후보 5개, 눌러서 선택
                [ 적용할 위치 코드 입력란 ]
                [승인] [거절]

 후보 단추를 누르면 코드 입력란이 채워진다. 직접 입력해도 된다.
 AI 가 못 맞혀도 관리자가 사진을 보고 정하면 되므로 제보는 버려지지 않는다.


6. 되돌리려면
----------------------------------------------------------------
 고르기 화면(spick)과 함수(pickOpen, pickChoose ...)는 지우지 않고 남겨 두었다.
 다시 쓰고 싶으면 sugSubmit 안의

     ai.verdict = 'unknown';
     ai.code = '';
     sugFinishSubmit(url, noteVal, ai, stat, noteEl);

 부분을 예전의 pickOpen(...) 호출로 되돌리면 된다.
 패치 스크립트 : D:\군산대\도구\patch_v59.ps1


7. 확인한 것
----------------------------------------------------------------
 - 제보 흐름에서 pickOpen 호출 : 없음
 - 위치 바꾸기 단추 display    : none
 - go('spick') 직접 호출       : pickOpen 안에만 1개 (도달 경로 없음)
 - 콘솔 오류                   : 없음

8. 왜 처음에 안 고쳐진 것처럼 보였나
----------------------------------------------------------------
 패치를 index_new.html 에만 넣었는데, 실제로 열어 본 주소는
 localhost:8081 의 index.html (패치 안 된 파일)이었다.
 서버가 두 개 떠 있어서 8080 이 아니라 8081 이 잡힌 것이다.

 → 지금은 index.html 에도 같은 패치를 넣었고, 서버도 하나만 띄운다.
   index.html      = 배포본 + v59 (흐름 변경만)
   index_new.html  = 배포본 + v58(정확도) + v59


9. 학습은 관리자 승인으로만 일어난다
----------------------------------------------------------------
 sugApprove() 안에 이미 이 줄이 있었다.

     if(typeof SUGAI !== 'undefined') SUGAI.learn(code, s.u, '건의함_'+id);

 사용자가 고르던 경로(pickChoose -> SUGAI.learn)는 v59 에서 닿을 수 없게 되었으므로,
 이제 AI 가 배우는 경로는 관리자 승인 하나뿐이다.
 위치를 가장 정확히 아는 사람이 가르치는 구조가 되었다.

 관리자 카드에 안내도 넣었다 :
   "✔ 승인하면 이 위치를 AI가 배웁니다 — 코드가 맞는지 확인해 주세요"
