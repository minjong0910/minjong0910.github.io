왜 하나
  1) 관리자 비밀번호 7자리가 앱 코드에 글자 그대로 적혀 있었다.
     사이트는 누구나 열 수 있어서 '페이지 소스 보기'로 누구나 볼 수 있었다.
     코드에서는 지웠지만 GitHub 의 예전 기록에는 남아 있다
     → 그 계정(admin@b3nav.app)은 더 쓰면 안 된다.
  2) 서버 규칙이 "로그인한 사람 = 관리자"였다. 계정만 만들 수 있으면 누구나 관리자였다.
     → "admins 명단에 있는 사람 = 관리자"로 바꾼다.

주소 : https://console.firebase.google.com/project/minjong-b974c

!! 순서가 중요합니다. 1 → 6 순서대로 하고, 7(새 앱 올리기)은 맨 마지막에 하세요.
   새 앱을 먼저 올리면, 서버에 명단이 아직 없어서 아무도 관리자로 못 들어갑니다.

----------------------------------------------------------------
1. 내 관리자 계정 만들기                                  (2분)
----------------------------------------------------------------
  왼쪽 메뉴 Authentication(인증) → Users(사용자) 탭 → [Add user / 사용자 추가]
    이메일   : 본인이 실제로 쓰는 이메일
    비밀번호 : 10자 이상, 숫자만 쓰지 말 것 (예전처럼 7자리 숫자 ✕)
  → 만들어진 줄의 "User UID(사용자 UID)" 칸 글자를 복사해 둔다. (예 : 8fK2...xQ1 — 28자쯤)

  관리자를 더 두려면 사람마다 이 과정을 따로 한다. 계정을 같이 쓰지 않는다.

----------------------------------------------------------------
2. 관리자 명단(admins) 만들기                              (2분)
----------------------------------------------------------------
  왼쪽 메뉴 Firestore Database → 데이터 탭 → [+ 컬렉션 시작]
    컬렉션 ID : admins
    문서 ID   : 1번에서 복사한 UID 를 그대로 붙여넣기   ← 자동 ID 를 쓰면 안 됨
    필드      : name (string) = 김민종
  → [저장]

  나중에 관리자를 바꿀 때는 이 명단에서 문서를 추가·삭제만 하면 된다. 앱은 고칠 필요 없다.

----------------------------------------------------------------
3. 새 규칙 붙여넣기                                       (1분)
----------------------------------------------------------------
  Firestore Database → 규칙 탭
  → 안에 있는 글자를 전부 지우고, D:\군산대\서버\firestore.rules 파일 내용을 통째로 붙여넣기
  → [게시]

----------------------------------------------------------------
4. 옛 공용 계정 막기                                      (1분)
----------------------------------------------------------------
  Authentication → Users → admin@b3nav.app 줄 오른쪽 ⋮ → [Disable account / 계정 사용 중지]
  (지워도 되지만, 막아 두면 나중에 기록을 볼 수 있다)

----------------------------------------------------------------
5. 아무나 계정을 못 만들게 하기                             (1분)
----------------------------------------------------------------
  Authentication → Settings(설정) 탭 → User actions(사용자 작업)
    [ ] Enable create (sign-up)   ← 체크 해제
    [ ] Enable delete             ← 체크 해제
  → [저장]
  (이제 계정은 콘솔에서만 만들 수 있다. 명단 규칙과 겹으로 막는 것)

----------------------------------------------------------------
6. 규칙이 제대로 막는지 시험하기 — 규칙 플레이그라운드        (5분)
----------------------------------------------------------------
  Firestore Database → 규칙 탭 → 오른쪽/아래 [규칙 플레이그라운드(Rules Playground)]
  아래 8가지를 하나씩 넣고 [실행]. 결과가 표와 같으면 정상입니다.

   #  시뮬레이션  위치(경로)             인증        넣을 것                         결과
   1  get         /suggestions/test     꺼짐        -                              거부 ✕
   2  create      /suggestions/test     꺼짐        문서: {"u":"data:image/jpeg;base64,AAAA", "status":"pending"}   허용 ○
   3  create      /suggestions/test     꺼짐        문서: {"u":"hello", "status":"pending"}                         거부 ✕
   4  create      /suggestions/test     꺼짐        문서: {"u":"data:image/jpeg;base64,AAAA", "status":"approved"}  거부 ✕
   5  get         /suggestions/test     켜짐 · UID 아무거나(예 abc)  -          거부 ✕
   6  get         /suggestions/test     켜짐 · UID = 내 UID(1번)     -          허용 ○
   7  create      /photos/x             켜짐 · UID 아무거나          문서: {"code":"13101"}   거부 ✕
   8  update      /admins/abc           켜짐 · UID = abc             문서: {"name":"x"}       거부 ✕

  6번이 거부되면 : 2번의 문서 ID 가 UID 와 똑같은지(앞뒤 공백 없이) 확인.

----------------------------------------------------------------
7. 새 앱 올리기                                           (맨 마지막)
----------------------------------------------------------------
  빌드가 만들어 둔 D:\군산대\깃허브_올릴파일 의 두 파일을 평소처럼 올린다.
  그 다음 관리자 로그인(첫 화면 로고 5번 탭) → 1번에서 만든 이메일·비밀번호.
    · "관리자 명단에 없는 계정입니다" → 2번 확인
    · 로그인 후 제보 목록이 안 뜬다     → 3번(규칙 게시) 확인
