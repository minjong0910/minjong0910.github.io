## 1. 왜 옥상을 못 맞혔나

앱에 등록된 사진 133장에 **옥상이 한 장도 없었기 때문**입니다. AI는 "앱에 있는 사진 중 가장 닮은 곳"을 찾는 방식이라, 정답표에 없는 장소는 답할 수가 없습니다.

실제로 확인해보니 학습 전에는 옥상 사진의 최고 유사도가 **0.483**이었습니다. 반려 기준(0.60)보다도 낮아서 AI는 "이건 내가 아는 곳이 아니다"라고 정확히 판단했습니다. **오작동이 아니라 정상 동작이었습니다.**

---

## 2. v45에서 달라진 것

### ① AI가 새 장소를 배웁니다

사진을 등록하거나 제보를 승인하면, **그 순간 AI가 그 사진의 특징을 계산해서 정답표에 추가**합니다. 브라우저에 저장되어 앱을 다시 열어도 유지됩니다.

```
사진 등록 → AI가 벡터 계산 → 정답표에 추가 → 다음 제보부터 인식
```

### ② 사진 여러 장을 주면 알아서 분류합니다

「넣을 위치 확인」 화면에 **「🤖 AI로 위치 찾기」** 버튼이 생겼습니다. 파일 이름에 호실번호가 없어도 사진을 보고 위치를 찾습니다.

| AI 판단 | 처리 |
|---|---|
| 유사도 75% 이상 & 격차 4%p 이상 | **위치 자동 배정** |
| 60~75% | 추천만 표시 (사람이 확인) |
| 60% 미만 | **처음 보는 장소**로 분류 |

### ③ 처음 보는 장소는 같은 곳끼리 묶어줍니다

옥상 사진 5장을 넣으면 AI가 **"이 5장은 서로 같은 장소이고, 앱에 등록된 어떤 곳과도 다르다"**까지 스스로 알아냅니다. 사람은 그 묶음에 **이름 한 번만** 입력하면 됩니다.

> **한글 이름도 됩니다.** 「옥상」이라고 적어두면, 나중에 제보 메모에 "옥상"이라고 쓴 것도 AI가 알아봅니다.

### ④ 제보 메모를 힌트로 씁니다

메모에 쓴 말에서 위치를 읽어냅니다.

| 메모 | 읽어낸 위치 |
|---|---|
| `13210호 문이 바뀌었어요` | 13210 |
| `3층 왼쪽 복도 게시판` | HALL3L |
| `4층 엘리베이터 앞` | EV4 |
| `정문 앞이 공사중이에요` | BLD |
| `지하에 새 안내판` | B1 |
| `옥상 실외기가 새로 생겼어요` | 옥상 *(학습한 뒤부터)* |

사진과 메모가 **같은 곳을 가리키면** 확신도가 올라가고, **다르면** 관리자 화면에 둘 다 보여줍니다.

## 3. 옥상을 등록하는 방법 (3분)

1. 폰으로 **옥상 사진 3~5장** 촬영 (각도를 조금씩 다르게)
2. 앱 → 첫 화면 **로고 5번 탭** → 비밀번호 → **사진 등록**
3. **파일 선택**으로 옥상 사진들 넣기
4. 「넣을 위치 확인」 화면에서 **「🤖 AI로 위치 찾기」** 누르기
5. **「🆕 처음 보는 장소 1 — 사진 5장」** 카드가 뜸
6. 입력칸에 **`옥상`** 입력 → **「이 묶음에 적용」**
7. 아래 **「N장 넣기」** 클릭

끝입니다. 이제 옥상 사진을 제보하면 AI가 「옥상」으로 알아봅니다.

## 4. 실제로 확인한 것

옥상 시나리오를 그대로 재현해서 측정했습니다.

| 단계 | 결과 |
|---|---|
| 학습 전, 옥상 사진 판정 | `irrelevant` (유사도 0.483) — 모르는 곳이라고 정확히 판단 |
| 옥상 사진 5장 자동 묶기 | **1묶음 [5장]** — 전부 같은 장소로 정확히 묶음 |
| 이름 「옥상」 입력 후 학습 | 5장 저장 |
| **학습에 안 쓴 6번째 옥상 사진** | **「옥상」으로 인식 (유사도 0.993)** |
| 기존 위치 3곳 재확인 | 13104 / 13304 / HALL5L 전부 정확 — 학습이 기존 인식을 방해하지 않음 |
| 새로고침 후 | 학습 5장 그대로 유지 |
| 메모 "옥상" + 옥상 사진 | 일치 표시 |
| 메모 "옥상" + 다른 곳 사진 | **불일치 표시** (관리자에게 경고) |

## 5. 배운 내용을 파일에 담기

「사진 등록」 화면의 **「사진 담아서 저장」**을 누르면, 이제 **사진과 함께 AI가 배운 내용도 파일에 담깁니다.** 그 파일을 깃허브에 올리면 다른 사람이 열어도 AI가 옥상을 알아봅니다.

> 안 그러면 학습 내용이 등록한 사람의 브라우저에만 남습니다.

**사진 등록 화면 아래**에 지금까지 배운 현황이 표시됩니다.

```
🤖 AI가 추가로 배운 사진 5장 · 위치 1곳 (옥상)
   배운 것 지우기
```

## 6. 정리 — 어디까지 자동이고 어디부터 사람인가

| 단계 | 누가 |
|---|---|
| 사진 100장 특징 계산 | **AI** |
| 기존 등록 장소와 대조 → 자동 배정 | **AI** |
| 남은 사진을 같은 장소끼리 묶기 | **AI** |
| 그 묶음의 **이름** 정하기 | **사람 (한 번)** |
| 이후 그 장소 인식 | **AI** |

AI는 "이 사진들이 같은 곳"이라는 건 스스로 알아내지만, 그 장소를 사람이 뭐라고 부르는지는 알 방법이 없습니다. **이름표 한 번**이 사람의 몫이고, 나머지는 전부 자동입니다.

이 구조가 발표에서도 설명하기 좋습니다 — *"학습 데이터를 따로 모으지 않고, 관리자가 사진을 넣는 행위가 곧 학습이 되도록 설계했습니다."*

---

## 7. 한계

- 학습은 브라우저 저장소를 쓰므로 **최대 400장**까지입니다. 넘으면 오래된 것부터 지워집니다.
- 앱에 원래 있던 133장 학습은 파일에 내장되어 있어 지워지지 않습니다. 「배운 것 지우기」는 추가로 배운 것만 지웁니다.
- 서버를 붙이면 학습 내용이 모든 사용자에게 공유됩니다. 지금은 등록한 사람 기기에만 남고, 「사진 담아서 저장」으로 파일에 담아야 다른 사람에게 전달됩니다.
