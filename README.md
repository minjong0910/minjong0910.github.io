# 공대 3호관 실내 길안내

군산대학교 공과대학 3호관(지하 1층 ~ 5층)의 실내 길안내 웹앱입니다.
사진 한 장으로 지금 어디에 있는지 알아내고, 3D 건물 모형 위에서 목적지까지 안내합니다.

- 졸업작품 · 김민종 · 손의윤 · 문성일
- 배포 : GitHub Pages — `index.html` + `aivec.js` 두 파일
- 설치 없이 폰 브라우저에서 동작합니다 (카메라·AI·글자 읽기 모두 브라우저 안에서)

## 어떻게 동작하나

```
사진 ──┬─▶ ① 글자 읽기 (Tesseract.js)
       │     호실 번호판 · 엘리베이터 층 표시 · 비상대피 안내판
       │     → 읽히면 그대로 확정 (오독 0건)
       │
       └─▶ ② 모양 비교 (MobileNetV2 α0.5, 1280차원)
             사진 1,753장으로 만든 기준벡터 4,847개와 비교
             → 상위 후보 + 확신도 + 복도 좌우
                    │
                    ▼
            ③ 관리자 승인 ── 승인하면 모든 기기가 배운다 (Firestore)
```

글자가 읽히면 글자를 믿고, 안 읽히면 모양으로 추정하되 **확정은 사람이 합니다.**
AI 가 틀린 위치를 스스로 배워 나빠지는 것을 막기 위해서입니다.

## 정확도

**다른 사람이 찍은 사진으로만** 잽니다. 같은 사람이 한 번에 찍은 사진(36개 묶음)은
기준에서 빼고 맞힙니다. 처음 온 사용자는 우리가 찍은 사진을 갖고 있지 않기 때문입니다.

| 종류 | 장수 | 정확한 자리 | 층 | 5등 안 |
|---|---:|---:|---:|---:|
| 전체 (강의실 제외) | 1,522 | 53.3% | 65.6% | 82.4% |
| 복도 | 920 | 55.3% | 67.3% | 82.7% |
| 라운지·로비 | 179 | 64.2% | 79.9% | 84.9% |
| 복도 — 같은 자리에서 두 장 | 909 | 61.9% | 73.8% | 88.2% |

**95% 신뢰구간** — 자리 45.5 ~ 58.2%, 층 60.6 ~ 69.7%. 같은 사람이 한 번에 찍은 사진은 함께 맞고
함께 틀리므로, 촬영 묶음 36개를 통째로 복원추출(2,000번)해 구했습니다. 사진을 독립으로 보면 폭이 절반으로 좁게 나옵니다.

**확신할 때만 답하면** — 1·2등 장소의 유사도 차이로 줄 세워 상위 10% 만 답하면 자리 94.1%, 층 98.0%.
절반으로 문턱을 정해 나머지 절반에 적용하면 자리 93.1%. (1등 유사도로 줄 세우면 상위 10% 도 60.5% — 확신도로 쓸 수 없습니다.)

글자 읽기 (오독 0건) : 복도 번호판 37% · 엘리베이터 안 층 97% · 비상대피 안내판 층 45%

### 이 방식이 정말 일을 하나 — 기준선과 제거 실험

같은 사진·같은 시험에서 **한 가지만 바꿔** 잽니다. 차이는 사진마다 짝지어 비교하고 묶음 단위 부트스트랩으로 검정합니다.

| 방식 | 정확한 자리 | 지금 앱과의 차이 (95% 구간) |
|---|---:|---|
| 우연 (152곳 중 아무거나) | 0.7% | |
| 가장 흔한 곳만 답하기 | 9.6% | |
| 색 분포 (RGB 8×8×8) | 8.1% | |
| 작은 흑백 사진 16×16 | 18.6% | CNN 이 +34.6%p (+27.9 ~ +39.1) — **의미 있음** |
| **CNN — 지금 앱** | **53.2%** | |
| CNN · 후처리 없이 정규화만 | 52.8% | 후처리가 +0.4%p (−1.3 ~ +2.0) — 우연과 구분 안 됨 |
| CNN · 주성분 5개 제거 | 55.1% | +1.9%p (+0.8 ~ +3.3) — 6가지 중 골라낸 값이라 새 사진으로 확인 전엔 채택 안 함 |
| + 번호판 조각 시점 (v58~v66) | 50.8% | 뺀 것이 +2.4%p (+0.4 ~ +5.0) — **의미 있음** (v67 결정 확인) |

이 페이지는 자신이 만든 "지금 앱" 벡터를 배포된 `aivec.js` 와 사진마다 견줘 파이프라인이 같은지 먼저 확인합니다
(코사인 0.9967 — 8비트 저장 오차).

측정 : `eval_all.html` 92초 · `eval_ablation.html` 약 10분. 한계는 [`한계와_대응.txt`](한계와_대응.txt).

## 폴더

| 경로 | 내용 |
|---|---|
| `index.html` | 앱 원본 (3D·AI·글자 읽기·건의함 전부). **기능 패치는 여기에 건다** |
| `도구/patch_v*.ps1` | 기능 패치. 번호 순서대로 원본에 한 번씩 적용된 기록 |
| `도구/patch_v58.ps1` | 빌드 — 원본 + 기준벡터 → 배포용 `index_new.html` + `aivec.js` |
| `gen.html` | 사진 → 기준벡터 생성 (`생성물/aivec_new.json`, 약 7분) |
| `eval_all.html` | 정확도 측정 — 발표 숫자 전부, 확신도별 정확도, 신뢰구간 (92초) |
| `eval_ablation.html` | 기준선 비교와 제거 실험 — 이 방식이 정말 일을 하나 (약 10분) |
| `eval_audit.html` | 사진 배치 감사 — 폴더를 잘못 들어간 사진 찾기 |
| `eval_build.html` | 빌드 검사 — 빌드한 앱이 AI 가 아는 모든 장소를 다루나 (`빌드.ps1` 이 씀) |
| `빌드.ps1` | 한 번에 빌드 + 검사 (`빌드_실행.bat`) |
| `한계와_대응.txt` | 이 시스템이 못 하는 것과 그 대응 |
| `ocrtest.html` | 글자 읽기 측정 |
| `batches.json` | 사진 1,753장 → 촬영 묶음(층·파일계열·기기). 측정의 기준 |
| `preview.ps1` | 미리보기 서버 (http://localhost:8080) |
| `lib/` | Tesseract.js · TensorFlow.js (인터넷 없이도 동작하도록) |
| `*.txt` | 측정 결과·작업 기록·촬영 안내 |

사진(2.9GB)은 저장소에 넣지 않습니다. 사진 이름 목록은 `batches.json` 에 있습니다.

## 빌드

```
1. 미리보기_실행.bat                     미리보기 서버 (http://localhost:8080)
2. 사진이 바뀌었으면 gen.html            「생성 시작」 → 생성물/aivec_new.json (약 7분)
3. 빌드_실행.bat                         빌드 + 검사 + 깃허브_올릴파일 에 복사 (약 20초)
4. eval_all.html                         「전체 측정 시작」 (약 90초)
```

`빌드.ps1` 은 지금까지 실제로 났던 사고를 자동으로 잡고, 하나라도 걸리면 멈춥니다.

| 검사 | 잡는 사고 |
|---|---|
| 사진(폴더·이름) = 기준벡터 | 사진을 옮기고 기준벡터를 다시 안 만듦 |
| batches.json = 사진 | 측정 숫자가 틀어짐 |
| `model/` 폴더 없음 | 로컬 모델 때문에 모든 판별이 틀어짐 |
| `v1xx` 주석 36종 | 3D 작업이 통째로 사라짐 (apply_all.py) |
| 앱을 띄워 152곳 전부 확인 | 새 장소를 앱이 몰라 제보가 거절됨 |
| 152곳 전부 3D 위 자리 (place3D) | 3D·길찾기·관리자 지도에 안 나오는 장소 |
| 길찾기 그래프 · 계단 없이 도달 | 어떤 장소에 갈 수 없음 |
| 안내 좌우 = 확정 목록, 안내 = 그래프 | "왼쪽으로 도세요"·"두 번째 방"이 틀림 |
| 실사 3D 를 실제로 띄움 | three.js 를 못 채워 실사 3D 가 빔 (v81) |
| 관리자 후보 평면도 152곳 | 어떤 장소가 1등이면 지도가 깨짐 |
| 25MB 미만 | 깃허브 웹 업로드 불가 |

앱 검사는 Edge 헤드리스로 `eval_build.html` 을 열어 빌드한 앱 안의 함수를 직접 부릅니다.
검사마다 일부러 망가뜨린 빌드로 실패를 잡는지 확인했습니다 (라운지를 접수 범위에서 뺌 ·
좌우 뒤집기 · '몇 번째' +1 · 5층 엘리베이터 끊기 · three.js 이름표 제거 · 지하 좌표 깨기).
망가뜨린 사본은 `eval_mut*.html` 처럼 이름을 지어야 미리보기 서버가 내어 줍니다.

3D 성능은 주소 뒤 `?perf=1` 로 재고, 테두리 선 합치기는 `?merge=1` 로 시험합니다 (`3D_성능_재는법.txt`).
코드가 안 바뀌었으면 `index_new.html` 은 바이트 단위로 같게 나옵니다 (두 번 빌드해 해시 확인).
