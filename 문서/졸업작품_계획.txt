0. 지금 상태 진단 (코드에서 확인한 사실)
----------------------------------------------------------------

 없는 것
   - 실시간 위치 추적 : IMU(가속도·자이로) 코드 0줄, BLE·WiFi·GPS·AR 전부 없음
   - 경로 탐색 알고리즘 : dijkstra / A* / adjacency / shortestPath 전부 0회
                          경유점을 손으로 박아둔 방식
   - 측정된 성능 숫자 : 하나도 없음
   - 건물 확장성 : FLOOR_LAYOUT 등 좌표가 소스에 박혀 있어 3호관 전용

 있는 것 (그리고 앞으로 핵심 부품이 될 것)
   - 정밀 3D 실내 모델 (v101~v151)  → 맵 매칭의 재료
   - 출입문 QR 4개                  → 절대 위치 보정점
   - 사진 위치판별 AI (기준벡터 399, 자료집 239장) → 랜드마크 보정점
   - 번호판 OCR                     → 강의실 단위 보정점
   - Firebase 제보·관리자 체계

 교수님이 "껍데기"라고 하신 이유
   길안내 앱인데 사용자가 어디 있는지 모른다.
   위치를 아는 세 방법(QR·사진·수동선택)이 전부 "사용자가 알려주는" 방식이고,
   한 번 알려주면 그 뒤로 갱신되지 않는다. 걷기 시작하면 앱은 사용자를 놓친다.
   지금 있는 것은 "정교한 3D 건물 뷰어 + 경로 재생기"다.


1. 이번 졸업작품의 핵심 주제
----------------------------------------------------------------

 제목(안)
   "정밀 실내 3D 모델을 제약조건으로 사용하는 저비용 실내측위
    — 보행자 추측항법(PDR)과 시각 랜드마크 보정의 결합"

 한 줄 요약
   비콘·WiFi 같은 추가 장비 없이, 폰 센서 + 이미 만든 3D 모델 + QR/사진만으로
   실내에서 사용자 위치를 끊기지 않고 추정한다.

 왜 이 주제가 좋은가
   - 지금까지 만든 것이 버려지지 않는다. 3D는 맵 매칭 재료로, QR·AI는 보정점으로 승격된다.
   - 비교 실험을 설계하기 쉽다 (아래 4장).
   - 추가 장비가 0원이라 "저비용"이라는 명확한 주장 포인트가 있다.
   - 특허를 낸다면 바로 이 측위 방법이 대상이다. 3D 모델 자체는 특허가 어렵다.

 시스템 구성
   [입력]  걸음 센서(가속도·자이로)      ── 항상 갱신, 오차 누적
           QR / 사진AI / 번호판OCR        ── 가끔, 정확
   [측위]  PDR 추측 → 맵 매칭(벽·복도 제약) → 랜드마크 보정으로 오차 리셋
   [경로]  실내 그래프 위 최단경로 탐색
   [표시]  기존 3D 화면에 "현재 위치" 표시


2. 10주 일정과 역할 분담
----------------------------------------------------------------

 역할 (이름은 팀에서 정하세요)
   A = 측위 엔진 담당 (지금 코드 주인이 맡는 것을 권함)
   B = 앱화 담당 (Capacitor, 센서 플러그인, APK)
   C = 평가·데이터·문서 담당

 ── 1~2주차 ────────────────────────────────────────────────
  C  [최우선] 이미 가진 것 측정하기.  새로 만들 것 없이 숫자가 나온다.
       · 사진 위치판별 Top-1 / Top-5 정확도
       · 층 판별 정확도
       · 유사도 임계값을 바꿔가며 정확도 곡선
       · 틀린 사례 모음 (어떤 장소끼리 헷갈리는가, 왜)
       · 번호판 OCR 인식률
     → 이 숫자가 나오는 순간 "껍데기"라는 평가의 절반이 사라진다.
        보고서 4장(실험)의 첫 번째 표가 여기서 나온다.

  B  index.html(20MB, 20,760줄) 파일 분리.
       html / css / 3D / 측위 / AI / UI 로 나눈다. 앱 빌드 전에 반드시 필요.
       이 단계에서 기능이 깨지지 않는지 확인하는 것이 핵심.

  A  PDR 기초 실험. 폰을 들고 걸으며 가속도·자이로 원시값을 기록하고 그래프로 본다.
       걸음이 가속도 파형에서 어떻게 보이는지 눈으로 확인하는 단계.

 ── 3~5주차 : 측위 엔진 (여기가 졸업작품의 핵심) ──────────────
  A  (1) 걸음 검출 : 가속도 크기의 봉우리 찾기 + 최소 간격(0.25초)으로 중복 제거
     (2) 보폭 추정 : 신장 x 0.415 로 시작 → 나중에 Weinberg 식으로 개선
     (3) 방향 추정 : 자이로 적분.
         ※ 실내 지자기는 철골·전자기기 때문에 많이 틀린다. 의존하지 말 것.
         ※ 건물 복도가 직교하므로 방향을 90도 단위로 스냅하면 오차가 크게 준다.
            이 아이디어 자체가 보고서에 쓸 만한 내용이다.
     (4) 맵 매칭 : 이미 있는 3D 모델에서 벽·복도 정보를 꺼내
         · 벽을 통과하는 이동은 막는다
         · 추정 위치를 복도 중심선에 투영한다
         → 3D를 정밀하게 만든 것이 여기서 정확도로 보상받는다
     (5) 랜드마크 보정 : QR·사진AI·번호판OCR이 성공하면 위치와 방향을 그 자리로 리셋

  B  Capacitor로 안드로이드 앱 만들기
       · 지금 웹 코드를 그대로 넣는다. 3D·AI·OCR 다시 안 만들어도 된다.
       · 센서는 네이티브 플러그인으로 받는다 (웹 API보다 안정적이고 정확)
       · 카메라 권한, 저장소 권한 처리
       · 목표: 5주차 안에 "폰에 설치되어 실행되는 APK" 확보
       ※ iOS는 이번 학기에 하지 말 것. 요구사항에 없고 시간이 없다.

  C  실험 설계와 정답 데이터 만들기
       · 경로 3개 선정 : 짧음(1층 내) / 중간(층 이동 1회) / 긺(2회 이상)
       · 각 경로의 정답 좌표와 체크포인트를 바닥에 표시해 측정 기준을 만든다
       · 기록 양식 준비 (엑셀)

 ── 6~7주차 : 통합과 측정 ──────────────────────────────────
  A+B  측위 엔진을 앱에 넣고 3D 화면에 "현재 위치" 점을 띄운다
  C    본 실험 수행 — 아래 4장 참조
  A    측정 결과를 보고 파라미터 조정 (보폭 계수, 스냅 각도, 보정 신뢰도)

 ── 8~9주차 : 마무리 ──────────────────────────────────────
  A  경로 탐색을 알고리즘으로 교체 (복도를 노드·간선 그래프로 만들고 최단경로 탐색)
     ※ 시간이 부족하면 이건 "향후 과제"로 미뤄도 된다. 측위가 우선이다.
  B  APK 안정화. 최소 2종류 폰에서 테스트 (센서 특성이 기기마다 다르다)
  C  보고서 작성, 그래프 작성

 ── 10주차 : 발표 준비 ────────────────────────────────────
     시연 시나리오 연습. 현장에서 인터넷이 끊길 경우를 대비해
     lib/ model/ 를 앱에 포함시켜 오프라인으로도 동작하게 해 둘 것.


3. 앱화 방법 — Capacitor를 권하는 이유
----------------------------------------------------------------

   방법                  작업량    센서 접근                 판단
   ------------------    ------    ---------------------     ----------
   PWA(홈화면 추가)      거의 0    웹 API 한정, iOS 제약 큼  임시방편
   Capacitor로 감싸기    1~2주     네이티브 플러그인 전부    << 권함
   네이티브 재작성       수개월    최상                      시간 없음

   Capacitor를 쓰면 지금 index.html 을 그대로 넣어 안드로이드 APK가 나온다.
   3D·AI·OCR을 다시 만들 필요가 없다. 측위에 필요한 IMU도 플러그인으로 안정적으로 잡힌다.

   준비물: Node.js, Android Studio
   주의  : 넣기 전에 20MB 단일 파일을 반드시 분리할 것 (1~2주차 B 작업)


4. 실험 설계 — 보고서의 심장
----------------------------------------------------------------

 비교군 (이 3개 비교가 보고서의 핵심 표가 된다)
   (가) PDR만
   (나) PDR + 맵 매칭
   (다) PDR + 맵 매칭 + 랜드마크 보정   <- 우리 방식

 측정 방법
   경로 3종 x 반복 5회 x 팀원 3명 = 45회
   (사람마다 보폭이 다르므로 3명이 각각 걷는 것이 중요하다)

 지표
   - 끝점 오차 (m)
   - 경로 중간 체크포인트별 오차
   - 오차 누적 곡선 (걸은 거리 대비 오차)
   - 오차 분포에서 50% 지점, 90% 지점 값
   - 랜드마크 보정 1회당 줄어든 오차량

 예상되는 결과 이야기
   "PDR만 쓰면 50m를 걸었을 때 오차가 O m까지 커지지만,
    맵 매칭으로 O m, 랜드마크 보정을 더하면 O m로 줄었다."
   이 문장 하나가 졸업작품의 결론이 된다.

 기록 예시
   경로  반복  방식  끝점오차(m)  보정횟수  비고
   ----  ----  ----  -----------  --------  ----


5. 보고서 목차 (안)
----------------------------------------------------------------
   1. 서론 — 실내에서 GPS가 안 되는 문제, 기존 방법(비콘/WiFi)의 비용 문제
   2. 관련 연구 — PDR, 맵 매칭, 시각 기반 측위
   3. 제안 방법 — 시스템 구성, 걸음 검출, 방향 추정, 맵 매칭, 랜드마크 보정
   4. 구현 — 3D 모델링, AI 위치판별, OCR, 안드로이드 앱
   5. 실험 및 결과 — 1~2주차 측정 + 4장 본 실험
   6. 결론 및 향후 과제 — 경로탐색 고도화, 다른 건물 확장, 상품화


6. 상품화로 가려면
----------------------------------------------------------------
 지금 막혀 있는 것
   건물 좌표가 소스에 박혀 있다. 3호관 말고는 쓸 수 없다.

 풀어야 할 것
   FLOOR_LAYOUT 등을 JSON 데이터로 분리한다.
   "3호관만 되는 것"과 "건물 데이터만 넣으면 되는 것"의 차이가
   졸업작품과 상품의 차이다.

 현실적인 수요처
   대학 캠퍼스, 병원, 대형 관공서, 전시장 — 실내에서 길 잃기 쉬운 큰 건물.
   특히 병원은 수요가 크고 예산도 있다.

 차별점으로 내세울 것
   비콘 설치가 필요 없다 = 초기 비용이 거의 0.
   기존 실내측위 업체 대부분은 비콘 설치비가 들어간다.

 단계
   졸업작품(3호관 실증) → 교내 다른 건물로 확장 → 창업지원단/교내 창업경진대회
   → 실제 수요처 1곳 시범 도입

8. 교수님께 다시 갈 때 가져갈 것
----------------------------------------------------------------
 말로 설명하지 말고 세 장을 만들어 간다.
   1) 시스템 구성도 — 입력(QR·사진·IMU) → 측위 → 경로 → 표시,
                      각 블록에 실제로 쓴 기술을 적는다
   2) 측정 결과 표 — 1~2주차에 뽑은 숫자
   3) 남은 계획과 일정 — 이 문서

 "3D를 열심히 만들었습니다" 가 아니라
 "측위 오차를 O m 에서 O m 로 줄였습니다" 로 말이 바뀌면 평가가 달라진다.


9. 위험 요소와 대비
----------------------------------------------------------------
 - 지자기 센서가 실내에서 많이 틀린다 → 자이로 + 복도 방향 스냅으로 우회
 - 기기마다 센서 특성이 다르다      → 최소 2종 폰에서 테스트
 - 보폭이 사람마다 다르다           → 팀원 3명으로 실험, 개인 보정값 입력 기능
 - 시연 현장 인터넷 불통            → lib/ model/ 을 앱에 포함해 오프라인 동작
 - 일정 지연                        → 경로탐색 알고리즘은 버려도 된다.
                                      측위 엔진과 실험은 절대 버리면 안 된다.
