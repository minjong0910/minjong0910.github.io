날짜 · 커밋은 git 기록(git show <커밋>)에서 그대로 옮겼다. 비밀번호 · 키 · 토큰은 적지 않는다.

앞으로 버그는 Issue 로 열고, 고친 커밋 메시지에 「Fixes #번호」를 붙인다 (그러면 Issue 가 저절로 닫히고 서로 이어진다).


문제가 생기면 어디를 보나
────────────────────────────────────────────────────────────────

  앱 설정 → 문제 기록 (pwa.js 의 DIAG)
      앱 판 · 오류 · 기기 · 그래픽칩 · 해상도 배율 · 폰재질 여부 · 인터넷 · 서비스 워커 · 서버(Firestore) 오류 코드.
      줄을 누르면 전부 복사된다 — 기기에서만 나는 문제는 이것부터 받는다.
  브라우저 콘솔
      3D 셰이더 오류 같은 그리기 오류. 폰 경로는 주소 끝에 ?perf=phone 을 붙이면 PC 에서도 켜진다.
  검사_실행.bat / 검사.ps1 (-Full)
      파일 · 앱 · 안전망(길안내 1,110가지 · 사진 174장 · 화면 글자 · 모양 · 3D 그림 15장) · 로드뷰(데스크톱 + 폰 경로).
  GitHub Actions 탭
      어느 검사가 왜 실패했는지. 검사가 실패하면 server-log(서버 기록 전체)를 7일 동안 내려받을 수 있다.
      서버 규칙 시험 · 배포 뒤 사이트 확인 결과도 여기 요약에 한 줄로 남는다.
  Firestore 규칙 플레이그라운드 (Firebase 콘솔)
      같은 요청을 재현해 허용 · 거부 확인 — 서버/보안_설정_안내.txt
  사이트가 정말 새 판인지
      https://minjong0910.github.io/sw.js 의 VERSION 이 저장소 site/sw.js 의 VERSION 과 같은가.
      다르면 사례 5 를 본다.

  확인한 기록 폰 경로로 재현하고 콘솔을 읽었다 :
             SHADER_NAME MeshPhongMaterial … ENVMAP_TYPE_CUBE_UV … syntax error
             옥상 장면에서 185개 재질이 이 상태였다.
  근본 원인   폰은 가벼워지려고 MeshStandardMaterial 을 MeshPhongMaterial 로 바꿔치기한다(view3d.js).

  수정       폰 바꿔치기에서 그 환경맵을 뗀다(view3d.js). 같은 경로의 관련 증상도 함께 —
             반사 세기가 기본값(최대)으로 남아 문 · 난간이 「투명해 보임」(Phong 에는 envMapIntensity 가 없음),
             계단현상 보정을 꺼서 얇은 의자 다리가 사라져 보임 → 보정을 켬.
  재발 방지   · 설정 → 문제 기록 에 「폰재질 · 고친 자리 N곳」이 남는다(ef2dfb6).
             · 2026-11-10 : 로드뷰 검사(tests/roadview.html, 검사.ps1 -Full · 매주 GitHub)가 데스크톱 재생 뒤
               같은 앱을 ?perf=phone 으로 다시 열어 폰 경로로 3장면을 재생하고, three.js 의 셰이더 오류를 실패로 센다.
               (그전에는 검사가 데스크톱 경로만 탔다 — 외부 점검 D-1 이 짚었다.)

사례 6 — 관리자 화면에서 아무나 쓴 값이 HTML 로 들어감 (2026-11-10 · 외부 점검 B-2 로 발견)
────────────────────────────────────────────────────────────────

  증상       (드러난 피해는 확인하지 못했다 — 외부 점검이 코드 구조를 보고 짚었다.)
             건의함 제보는 익명으로 누구나 쓰고, 관리자 화면(suggest.js)은 제보를 문자열로 이어 innerHTML 로 그린다.
  확인한 기록 · 사진 칸 u 를 <img src="…"> 에 그대로 넣었다 — 규칙은 「data:image/아무거나;base64, 뒤에 아무 글자나」를 받았다.
               따옴표로 속성을 빠져나가 onerror 를 붙일 수 있었다.
             · 출입문 QR 칸(qr)은 「20자 아무 글자나」, AI 결과(ai)는 「map 이면 아무거나」를 받았다.
             · 고친 뒤 브라우저에서 꾸민 제보(사진 칸에 따옴표 + onerror, QR 칸에 <svg onload>)를 관리자 화면에 그려
               스크립트 실행 0 · 위험한 속성 0 을 확인했다.
  근본 원인   ① 서버 규칙이 모양을 느슨하게 받았다 ② 앱이 서버에서 받은 값을 그대로 HTML 문자열에 넣었다.
             관리자 브라우저에서 스크립트가 돌면 그 관리자 권한(승인 · 삭제 · 방 정보 수정)으로 무엇이든 할 수 있다.
  수정       세 겹으로 막는다.
             ① 서버 규칙 : 사진은 jpeg · png · webp 의 base64 만, QR 은 MAIN|BACK|EAST|WEST 만, AI 칸 60개 이하,
               승인 사진(photos)에도 모양 검사(validPhoto).
             ② 받을 때 : sugdb.js 의 cleanSug · cleanPhoto — 모양이 틀린 값은 버리거나 글자만 남긴다.
             ③ 그릴 때 : 사진 값 모양이 맞을 때만 <img> 에 넣고, 아니면 「⚠ 사진 형식이 맞지 않는 제보 — 거절해 주세요」.
               방 정보 설명(roomfix.js)도 글자로 바꿔 넣는다.
             관리자 작업은 adminlog 에 남는다(승인 · 거절 · 삭제 · 사진 올리기 · 숨기기 — 고치거나 지울 수 없다).
  재발 방지   · tests/check.html 「아무나 쓴 제보」 — 일부러 꾸민 제보를 관리자 화면에 그려 스크립트 0 · 위험한 속성 0 을 확인.
             · tests/rules — 꾸민 사진 값 · 태그를 넣은 QR · 큰 AI 칸이 서버에서 거부되는지 실제 요청으로 확인.
             · 규칙은 콘솔에 게시해야 적용된다 — 서버/firestore.rules 머리말의 「게시한 날」.


사례 7 — 건물과 무관한 사진에도 장소를 말함 (2026-11-10 · 사용자 보고 · 외부 점검 A-2)
────────────────────────────────────────────────────────────────

  증상       건의함에 풍경 · 화면 캡처 같은 사진을 올려도 「○○ 같아요」라고 장소를 댔다.
  확인한 기록 · sugai.js 의 「무관한 사진」 문턱(RELEVANT)이 0.15 였다. 재 보니 무관한 사진의 1등 유사도는
               가운데 값이 0.28~0.39, 가장 높은 것이 0.87 이라 품질 검사(흐림 · 어두움)에 걸리지 않으면 모두 통과했다.
             · 「어디에서 찍으셨나요?」에서 사용자가 고른 답을 확인 없이 그 폰의 AI 에 바로 가르쳤다(aid.js).
  근본 원인   가장 닮은 곳을 찾는 방식은 어떤 사진이 와도 「가장 가까운 곳」을 돌려준다.
             그런데 문턱을 「모르는 사진을 거르는 힘」으로 잰 적이 없었다(정확도 측정에 건물 밖 사진이 없었다).
  수정       · 도구/AI_건물밖사진_측정.ps1 · tests/ai_reject.html 로 앱과 같은 판정을 3호관 사진 145장 · 무관한 사진 182장에 돌려
               문턱을 0.44 로 정함 → 3호관 99.3% 그대로 · 무관 81.9% 거름. 결과 : 문서/AI_건물밖사진_측정.txt
             · 문턱보다 낮으면 장소를 대지 않고 「건물과 관련 없는 사진 같아요」 + 「그래도 보내기」. 번호판 글자가 읽히면 건물 사진으로 본다.
             · 사용자가 고른 답은 관리자가 확인한 뒤에만 AI 가 배운다.
  재발 방지   문턱이나 AI 자료를 바꾸면 도구/AI_건물밖사진_측정.ps1 을 다시 돌려 README 「정확도」에 함께 적는다.
             한계 : 다른 건물의 비슷한 복도는 측정에 없다.
